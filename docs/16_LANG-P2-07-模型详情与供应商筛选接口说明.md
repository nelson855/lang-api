# LANG-P2-07 模型详情与供应商筛选接口说明

无需认证的 `GET /portal/api/models/{modelId}` 与 `GET /portal/api/model-providers`，与现有 `GET /portal/api/models` 共享同一进程内目录快照及同一 `pricingVersion`。当前基线 `p2-2026-09-22-a` 下只有模型编号、供应商名称、可用性、基础价格具备证据，其余新增字段统一返回 `null`，不推断、不伪造。

## 模型引用编码

路径中的 `{modelId}` 不是原始模型编号，而是按下式生成的规范引用：

```text
modelRef = base64url_without_padding(UTF-8(目录模型 id))
```

- 客户端从列表 `id` 用 UTF-8 转字节后做网址安全 Base64 无填充编码；服务端只接受 `[A-Za-z0-9_-]+`，拒绝 `=` 填充与非法字符，严格 UTF-8 解码后要求重编码与输入完全一致，再校验目录编号边界（非空、长度 1~128、无控制字符）。
- 解码结果不裁剪、不折叠大小写、不做 Unicode 归一化，必须与快照键精确一致。
- 含 `/`、`%`、空格、中文表情的编号经编码后仍是单路径段，返回的 `model.id` 保持原值。

前端可用 `TextEncoder` 加网址安全 Base64 规则生成详情路由；展示时始终显示真实模型编号，引用只承担路由职责。

## `GET /portal/api/models/{modelId}`

不接受查询参数；除查询方法外返回统一 405。

### 请求示例

```text
GET /portal/api/models/YWJj
```

### 响应示例（当前基线）

```json
{
  "requestId": "req_xxx",
  "data": {
    "pricingVersion": "p2-2026-09-22-a",
    "model": {
      "id": "abc",
      "displayName": null,
      "provider": "Example",
      "availability": "AVAILABLE",
      "pricing": {
        "mode": "TOKEN",
        "currency": "USD",
        "unit": "PER_MILLION_TOKENS",
        "input": "10.0",
        "output": "20.0",
        "request": null
      },
      "contextWindowTokens": null,
      "maxOutputTokens": null,
      "inputModalities": null,
      "outputModalities": null,
      "capabilities": {
        "toolCalling": null,
        "reasoning": null,
        "structuredOutput": null,
        "attachments": null
      },
      "releaseDate": null,
      "description": null,
      "tags": null,
      "sortOrder": null,
      "enhancedPricing": null
    }
  }
}
```

### 字段空值语义

- `null` 表示来源缺失或证据不足；只有可信来源明确给出空集合才返回 `[]`；布尔能力只有明确证明不支持才返回 `false`。
- `capabilities` 对象始终存在，内部四个字段可空。
- `inputModalities` / `outputModalities` 有证据时只允许 `TEXT`、`IMAGE`、`AUDIO`、`VIDEO`、`FILE`。
- `releaseDate` 有值时使用 ISO 8601 日历日期。
- 上游新增未知字段、`supported_endpoint_types`、所有者、厂商图标、倍率、分组、渠道不会被映射成模态、能力、描述或标签。

## `GET /portal/api/model-providers`

不接受查询参数；除查询方法外返回统一 405。

### 响应示例

```json
{
  "requestId": "req_yyy",
  "data": {
    "pricingVersion": "p2-2026-09-22-a",
    "providers": [
      {"value": "DeepSeek", "label": "DeepSeek", "modelCount": 2},
      {"value": "OpenAI", "label": "OpenAI", "modelCount": 1}
    ]
  }
}
```

### 派生规则

- 只读取最终模型数组中的非空供应商，以裁剪后的完整名称同时作为 `value` 与 `label`，大小写敏感去重并累计 `modelCount`，按名称自然顺序稳定排序。
- 供应商为 `null` 的模型不计入，不制造“其他”供应商；同名不同上游厂商编号自然合并；无已知供应商时返回空数组。
- 不返回上游厂商编号、图标、渠道、分组、倍率、路由。

## 价格单位

- 详情 `pricing` 与同版本列表完全一致：`TOKEN` 按每百万 Token 的美元计，`REQUEST` 按每次请求的美元计，金额为十进制字符串。
- `enhancedPricing` 只有来源、计费维度、币种、单位、数值全部验证后才成为数组，每项含 `type`、`currency`、`unit`、非负十进制字符串 `price`；`type` 只允许 `CACHE_INPUT`、`CACHE_OUTPUT`、`IMAGE_INPUT`、`IMAGE_OUTPUT`、`AUDIO_INPUT`、`AUDIO_OUTPUT`、`VIDEO`、`SEARCH`。当前基线无增强计费证据，统一返回 `null`，不用零价或空数组暗示已验证无额外收费。

### 2026-10-02 TOKEN 实样记录

已在冻结的本地 New API 环境以默认组完成一次 `deepseek-v4-flash` 文本调用。脱敏用量日志记录输入 `108` Token、输出 `252` Token、默认组倍率 `1x`、基础费率 `$75 / 1M tokens`、实际花费 `$0.027000`；计算式为 `(108 + 252) × 75 / 1,000,000 = 0.027`，与日志一致。

本轮完整 Maven 与 Docker 构建通过后，按授权执行主 Compose `up -d --build`。新镜像的 `GET /portal/api/models`、`GET /portal/api/models/ZGVlcHNlZWstdjQtZmxhc2g` 与 `GET /portal/api/model-providers` 均返回 200，三者 `pricingVersion` 相同；该模型列表与详情的 `pricing` 完全一致：`mode=TOKEN`、`currency=USD`、`unit=PER_MILLION_TOKENS`、`input=75.0`、`output=75.0`、`request=null`，列表与详情均为 `Cache-Control: no-store`。结合上述既有脱敏真实扣费样本，运行时交叉核对任务已完成；本轮未重新发起付费模型调用。上下文、输出上限、输入/输出模态、四项能力、发布信息、描述、标签、排序与增强价格仍为 `null`。此记录不包含 API Key、会话标识、请求编号或上游凭据。

### 2026-10-02 增强字段来源核查

已核查 [OpenCode Go 模型与价格说明](https://dev.opencode.ai/docs/go/) 和 [DeepSeek 官方价格说明](https://api-docs.deepseek.com/quick_start/pricing/)。两者都包含与 `deepseek-v4-flash` 相关的 Token 与缓存计费信息；DeepSeek 还说明该旧模型名会路由到较新的 Flash 模型。它们不能直接成为本目录增强字段的来源，原因如下：

- 本地 New API 对该接入模型记录的对外基础价格为 `$75 / 1M tokens`，与公开上游的 Token 价格不同；当前没有可信证据说明两种价格之间的换算关系、账单归属或缓存价格如何透传。
- 接入路径是 OpenCode Go 订阅渠道，不是直接调用 DeepSeek API；因此 DeepSeek 的模态、上下文或缓存语义不能自动归属于当前 Portal 渠道。
- 可观察到的模型数据页面不是当前渠道的契约来源，不能用来承诺上下文窗口、最大输出、发布日期、能力或标签。

在取得当前渠道对缓存、图片、音频、视频、搜索、上下文上限和能力字段的明确接口契约及计费单位前，`enhancedPricing`、限制、模态、能力、发布信息、描述、标签和排序继续为 `null`。这不是“已验证无额外收费”或“明确不支持”。

## 版本一致性

- 列表、详情、供应商选项由一次上游加载原子生成，共享完整成功快照；失败不缓存，到期刷新失败不回退无期限旧快照。
- 三个响应均返回 `pricingVersion` 与 `Cache-Control: no-store`。列表与后续请求可能跨越刷新边界，客户端发现版本不同时应成对重取，不拼接不同版本使用。

## 错误行为

| 场景 | 状态与编码 |
|---|---|
| 非规范引用（空值、填充符、非法字符、非规范重编码、非法 UTF-8、不满足编号边界、多余路径段） | 400 `INVALID_ARGUMENT`，访问上游前拒绝，不记录原文 |
| 规范引用但快照无精确匹配 | 404 `NOT_FOUND`，不返回相似模型 |
| 任意查询参数 | 400 `INVALID_ARGUMENT` |
| 非查询方法 | 405 `METHOD_NOT_ALLOWED` |
| 上游超时、不可用、冲突数据 | 目录统一上游错误，无部分数据 |
| 未知路径 | 404 `NOT_FOUND` |

响应体统一为 `{requestId, data, error}`，成功时 `error` 为空，失败时 `data` 为空。响应不含厂商编号图标、倍率分组渠道、所有者端点、上游地址与原始包装。
