# 常用运行与验证命令

本文作为本系统日常命令的统一查阅入口。除前端独立命令明确要求进入 `frontend/` 外，所有命令均在仓库根目录执行。

## 1. 本地启动：同时使用系统与 New API 管理后台

本地需要访问 New API 管理后台时，使用这一条完整命令：

```bash
docker compose --env-file deploy/.env \
  -f deploy/compose.yml \
  -f deploy/compose.ops.yml \
  up -d --build
```

`-f` 用于指定配置文件；第二份文件叠加管理端口配置。`--build` 在启动前构建自研镜像，`-d` 表示后台运行。

| 默认入口 | 地址 | 用途 |
|---|---|---|
| Lang API | http://localhost:8081 | 系统页面及 Portal API |
| OpenAI 兼容模型网关 | http://api.localhost:8081/v1 | 模型调用 Base URL |
| New API 管理后台 | http://127.0.0.1:13000 | 上游账号、渠道、模型与计费管理 |

端口可通过 `deploy/.env` 中的 `EDGE_HTTP_PORT`、`NEW_API_ADMIN_PORT` 调整；域名和模型 Base URL 也以该文件的实际配置为准。管理端口仅绑定本机回环地址。

前提：Docker 可用，`deploy/.env` 已填写，New API 已完成初始化。仅首次缺少配置文件时复制模板，再填写本地参数；已有 `.env` 时不要覆盖：

```bash
cp deploy/.env.example deploy/.env
```

首次初始化与密钥填写见 [New API 初始化与升级手册](new-api/初始化与升级手册.md)。Compose 构建使用仓库的 `deploy/maven-settings.docker.xml`；下文宿主机 Maven 命令使用本机指定 settings.xml。

## 2. 仅启动业务服务：关闭 New API 管理入口

```bash
docker compose --env-file deploy/.env \
  -f deploy/compose.yml \
  up -d --build
```

此命令提供 Lang API 与模型网关，**不开放 13000 管理端口**。即使此前打开过管理入口，重新按主文件启动也可能重建 New API 容器并移除端口映射；`up` 会按本次配置调整运行容器，不能依赖旧端口一直保留。

如果希望持续使用管理后台，后续启动或重建始终使用第 1 节的两个 `-f`。

## 3. 单独打开管理入口与检查状态

只打开管理入口，不重建其他服务：

```bash
docker compose --env-file deploy/.env \
  -f deploy/compose.yml \
  -f deploy/compose.ops.yml \
  up -d --no-deps new-api
```

检查服务状态、管理端口及健康响应：

```bash
docker compose --env-file deploy/.env -f deploy/compose.yml -f deploy/compose.ops.yml ps
docker compose --env-file deploy/.env -f deploy/compose.yml -f deploy/compose.ops.yml port new-api 3000
curl --fail --silent --show-error http://127.0.0.1:13000/api/status
curl --fail --silent --show-error http://localhost:8081/healthz
```

默认端口下，`port` 应显示 `127.0.0.1:13000`。New API 健康检查使用 GET；服务健康不等于已经完成管理员初始化。

查看服务日志（日志仅供本地诊断，分享前去除敏感信息）：

```bash
docker compose --env-file deploy/.env -f deploy/compose.yml -f deploy/compose.ops.yml logs --tail=100 lang-api new-api edge-nginx
```

## 4. 停止与删除容器：保留数据

停止服务，保留容器和数据卷：

```bash
docker compose --env-file deploy/.env -f deploy/compose.yml -f deploy/compose.ops.yml stop
```

删除容器和项目网络，保留命名数据卷；下次用第 1 节命令重建：

```bash
docker compose --env-file deploy/.env -f deploy/compose.yml -f deploy/compose.ops.yml down
```

不要给日常停止命令添加 `-v`，该参数会删除命名卷及其业务数据。数据重置与备份恢复单独参见 [New API 初始化与升级手册](new-api/初始化与升级手册.md)。

## 5. 宿主机完整构建与后端验证

需要 Java 21、Maven 3.8.4。完整构建及验证会安装项目固定 Node/npm，执行前端 lint、单测、build，以及后端测试和集成 JAR 打包：

```bash
/Users/nelson/software/apache-maven-3.8.4/bin/mvn \
  -s /Users/nelson/software/apache-maven-3.8.4/conf/settings.xml \
  clean verify
```

产物：`portal-api/target/portal-api-0.1.0-SNAPSHOT.jar`，内含前端静态资源。使用 `clean` 避免旧前端资源残留。本机 Maven 制品仓库固定为 `/Users/nelson/software/apache-maven-3.8.4/repository`。

只运行后端测试，不重新打包既定验收 JAR：

```bash
/Users/nelson/software/apache-maven-3.8.4/bin/mvn \
  -s /Users/nelson/software/apache-maven-3.8.4/conf/settings.xml \
  -pl portal-api test
```

宿主机生成 JAR 不会自动更新正在运行的 Docker 容器；同步容器代码仍需执行第 1 节构建启动命令。环境切换和后端独立启动见 [工程构建与本地启动说明](07_工程构建与本地启动说明.md)。

## 6. 前端独立开发与检查

先运行一次完整 Maven 构建，安装固定的 Node/npm。然后在一个终端中执行：

```bash
cd frontend
export PATH="$PWD/node:$PATH"
node node/node_modules/npm/bin/npm-cli.js run dev
```

开发页面默认位于 `http://localhost:5173`。当前 Vite 配置没有后端代理，因此仅启动 Vite 不代表已具备完整真实登录与业务接口链路；完整系统联调使用第 1 节的 Compose 入口。

以下命令同样在 `frontend/` 中、设置上述 PATH 后执行，按需选择：

```bash
node node/node_modules/npm/bin/npm-cli.js run lint
node node/node_modules/npm/bin/npm-cli.js test -- --maxWorkers=2
node node/node_modules/npm/bin/npm-cli.js run build
node node/node_modules/npm/bin/npm-cli.js run test:e2e
```

浏览器测试前先执行 build。默认 Playwright 使用构建预览和可控接口响应，不能作为真实 New API 数据验收证据。前端细节见 [前端开发说明](09_前端开发说明.md)。

## 7. 第二阶段聚合验收

在仓库根目录执行：

```bash
python3 integration-tests/aggregation/acceptance.py contract
python3 integration-tests/aggregation/acceptance.py local
python3 integration-tests/aggregation/acceptance.py performance
python3 integration-tests/aggregation/acceptance.py all
```

各集合含义、专用测试身份、构建一致性、报告保存和冷热采样前提见 [聚合验收运行说明](../integration-tests/aggregation/README.md)。验收命令不自动构建、重启或发布服务；缺少前提及尚未完成的检查明确记录为 BLOCKED。

退出码：`0` 为所选适用检查通过，`1` 表示存在 FAIL，`2` 表示没有 FAIL 但存在 BLOCKED。所选检查通过不等于第二阶段上线条件通过。
