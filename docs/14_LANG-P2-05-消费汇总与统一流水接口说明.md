# LANG-P2-05 消费汇总与统一流水接口说明

受保护的 `GET /portal/api/account/consumption-summary` 与 `GET /portal/api/account/transactions`，为当前用户提供基于冻结口径 `p2-2026-09-22-a` 的消费汇总与统一只读流水。两个接口共享同一 `ConsumptionSnapshot` 缓存，复用 P2-02 的查询上下文、读取预算与观测。现有 `/portal/api/account/balance`、`/portal/api/account/topups`、`/portal/api/account/topup-options` 行为完全不变。

## 共同约定

- 必须携带 Portal 会话 Cookie（`LANG_SESSION` + `LANG_UID`），否则 `UNAUTHENTICATED`/401。
- 认证主体与 Cookie 中的用户 ID 必须一致；不一致返回 `UNAUTHENTICATED`。
- 只接受文档中列出的参数；任何未知参数、`userId`、`baselineVersion`、`tokenId`、`channel` 等都返回 `INVALID_ARGUMENT`/400，且不访问上游。
- 时间参数为带偏移量的秒级 ISO 8601，左闭右开 `[startTime,endTime)`，必须 IANA 时区；当前粒度跨度复用聚合配置（`HOUR` 7 天等）。
- 当前基线 `p2-2026-09-22-a` 下实时日志上限 7 天（`max-live-log-range=168h`）；超过即 `INVALID_ARGUMENT`，不读取上游。

## `GET /portal/api/account/consumption-summary`

### 请求参数

| 参数 | 必填 | 说明 |
|---|---|---|
| `startTime` | 是 | ISO 8601 秒级时间 |
| `endTime` | 是 | 晚于 `startTime` |
| `granularity` | 是 | `FIVE_MINUTES` / `HOUR` / `DAY` |
| `timezone` | 是 | IANA 时区 |

### 响应示例

```json
{
  "requestId": "req_xxx",
  "data": {
    "baselineVersion": "p2-2026-09-22-a",
    "range": {
      "start": "2026-09-01T00:00:00Z",
      "end": "2026-09-08T00:00:00Z",
      "timezone": "UTC",
      "granularity": "HOUR"
    },
    "recordCount": {"value": "3", "unit": "records", "availability": "AVAILABLE", "reasonCode": null},
    "quotaTotal": {"value": "60", "unit": "quota", "availability": "AVAILABLE", "reasonCode": null},
    "moneyTotal": {"value": null, "currency": null, "availability": "UNAVAILABLE", "reasonCode": "CURRENCY_CONVERSION_NOT_VERIFIED"},
    "coverage": {"type": "CONSUMPTION", "availability": "AVAILABLE", "reasonCode": null}
  }
}
```

### 字段含义

- `recordCount`：当前范围内完整读取的 type=2 消费日志条数。
- `quotaTotal`：精确累计的原始 quota，非负十进制字符串。
- `moneyTotal`：**当前基线下不可用**。由于 `quotaPerUsd` 未取得独立验证证据，固定返回 `UNAVAILABLE + CURRENCY_CONVERSION_NOT_VERIFIED`，`value`/`currency` 均为 `null`。不会读取 `catalog.quota-per-usd` 配置生成"参考 USD"。
- `coverage`：消费日志来源覆盖状态。
  - `AVAILABLE`：范围内所有 type=2 记录都带有非空 `requestId`。
  - `PARTIAL + MISSING_STABLE_REFERENCE`：存在缺 `requestId` 的记录；它们仍计入 `recordCount` 与 `quotaTotal`，但不进入 `/transactions` 流水。
  - `UNAVAILABLE`：读取失败，整体请求会失败，不返回部分汇总。

## `GET /portal/api/account/transactions`

### 请求参数

在汇总参数基础上额外接受：

| 参数 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `page` | 否 | `1` | 从 1 开始 |
| `pageSize` | 否 | `20` | 1~100 |
| `type` | 否 | 全部 | `TOPUP` / `CONSUMPTION` / `REFUND` |

`page * pageSize` 超过 `aggregation.max-records`（当前 200）即 `INVALID_ARGUMENT`，不会扫描后再丢弃。

### 响应示例（全部类型）

```json
{
  "requestId": "req_yyy",
  "data": {
    "baselineVersion": "p2-2026-09-22-a",
    "range": { "start": "...", "end": "...", "timezone": "UTC", "granularity": "HOUR" },
    "type": null,
    "page": 1,
    "pageSize": 20,
    "total": 2,
    "availability": "PARTIAL",
    "reasonCode": null,
    "coverage": [
      {"type": "TOPUP", "availability": "UNAVAILABLE", "reasonCode": "BASELINE_NOT_VERIFIED"},
      {"type": "CONSUMPTION", "availability": "AVAILABLE", "reasonCode": null},
      {"type": "REFUND", "availability": "UNAVAILABLE", "reasonCode": "SOURCE_NOT_AVAILABLE"}
    ],
    "items": [
      {
        "transactionId": "CONSUMPTION_<64 位十六进制>",
        "occurredAt": "2026-09-01T12:00:00Z",
        "type": "CONSUMPTION",
        "direction": "DEBIT",
        "amount": "60",
        "unit": "QUOTA",
        "currency": null,
        "status": "SUCCEEDED",
        "remark": "gpt-4o",
        "referenceId": "req-abc"
      }
    ]
  }
}
```

### 单类型查询行为

- `type=CONSUMPTION`：仅返回消费 coverage 与 items。
- `type=TOPUP`：返回 `items=[]`、`total=0`、总体 `UNAVAILABLE + BASELINE_NOT_VERIFIED`，**不读取消费日志**，也不调用 P1 充值接口。
- `type=REFUND`：返回 `items=[]`、`total=0`、总体 `UNAVAILABLE + SOURCE_NOT_AVAILABLE`。
- 省略 `type`：默认查全部；TOPUP/REFUND 不可用，总体固定 `PARTIAL`。

### 流水 item 字段

| 字段 | 说明 |
|---|---|
| `transactionId` | `CONSUMPTION_` + lowercaseHex(SHA-256(`"CONSUMPTION\0" + userId + "\0" + requestId`))，不可逆且跨用户隔离；不暴露内部数据库 ID |
| `occurredAt` | UTC ISO 8601 |
| `type` / `direction` | 当前消费固定 `CONSUMPTION` / `DEBIT` |
| `amount` | 非负十进制字符串（原始 quota），方向不靠正负号表达 |
| `unit` / `currency` | `QUOTA` 时 `currency=null`；`CURRENCY` 时必须显式提供币种 |
| `status` | 当前消费固定 `SUCCEEDED` |
| `remark` | 模型名（可空） |
| `referenceId` | 上游 `requestId`（可空） |

### 排序与分页

- 按 `occurredAt` 降序、`transactionId` 升序。
- `total` 为本次筛选下**可投影** item 的准确总数；缺 `requestId` 的记录不进 `total`。
- 同一快照重复请求返回相同顺序；相邻页不重复、不漏项。
- 同一快照内出现重复 `transactionId`（两条不同记录的 requestId 哈希冲突）会让整个请求安全失败，不会静默去重或追加序号。

## 缓存与一致性

- 两个接口共享同一 `account-consumption-snapshot` 缓存键（用户 + 范围 + 粒度 + 时区 + baseline + 筛选）。
- TTL 为 30 秒，容量 1000；命中时响应仍使用当前请求的 `requestId`。
- 失败、超时、保护性拒绝均不进入缓存。
- 快照内容只保留 `occurredAt`、`requestId`、`model`、`rawQuota` 与缺失引用计数；不缓存 tokenId、Key 名称、渠道、原始日志或会话。

## 观测

- 操作命名空间：`account-consumption-snapshot`、`account-consumption-summary`、`account-transactions`。
- 指标：`portal.aggregation.duration`、`portal.aggregation.cache`、`portal.aggregation.upstream.{calls,pages,records}`、`portal.aggregation.rejections`。
- 不引入用户 ID、type 筛选、时间范围、requestId、model 等高基数标签。
- 日志只记录当前 Portal `requestId` 与有限拒绝原因。

## 当前阻塞与边界

- `moneyTotal` 需要 `quotaPerUsd` 独立验证证据；当前固定 `UNAVAILABLE`。
- 充值流水需要 `/api/user/topup/self` 的真实状态、金额、时间与稳定引用证据；当前仅返回 `UNAVAILABLE + BASELINE_NOT_VERIFIED`。
- 退款流水当前没有来源字段；`UNAVAILABLE + SOURCE_NOT_AVAILABLE`。
- 接口只读；不会写入、修改或补记 New API 记录，也不影响 `/portal/api/account/balance` 的权威余额。
