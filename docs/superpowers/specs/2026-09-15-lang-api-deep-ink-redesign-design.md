# Lang API Deep Ink 全站视觉重构设计

## 目标

将现有前端从基础功能骨架重构为独立、简洁且轻度科技化的大模型 API 产品界面。设计语言命名为 **Deep Ink / 深墨**：深色页面、克制的层级、薄荷绿单一信号色，以及由真实 API 请求与数据排版构成的技术感。

本次覆盖全部现有路由：公开首页、模型广场、开发文档、服务地区、用户协议、隐私政策、登录、注册、Dashboard、API 密钥、请求日志、钱包、个人设置与 404/通用状态。

## 已确认的设计决策

- 全站默认采用深色主题；控制台使用较高明度的深灰表面，避免长时间使用时压迫。
- 首页采用 B2 分栏结构：中文价值主张在左，代码终端在右。英文仅用于品牌、协议、代码和技术标签。
- 品牌色板：`Void #0D1117`、`Carbon #131920`、`Slate #1B232D`、`Paper #EEF2F4`、`Mist #929DAA`、`Signal #7CF2C7`。
- 核心识别元素为“实时请求轨迹”：在首页演示、请求日志、用量等场景中用受控的状态行、等宽文本和轻量标记呈现请求进程；不使用霓虹网格、装饰性粒子或强发光。
- 首页不复用通用的多张“卖点卡”结构。内容顺序为价值主张与快速接入、协议可信度、真实模型目录预览、真实三步接入、行动入口与页脚。
- 控制台保持固定侧栏和简洁顶栏；各业务页以数据、筛选和操作为主，不复制首页的大标题或终端装饰。

## 信息架构与页面设计

### 公开页面

`PublicLayout` 使用半透明深色顶栏、明显的当前导航、主要行动按钮和三栏页脚。移动端仍使用现有可访问抽屉，但视觉上与桌面导航共享同一层级与标签。

首页首屏左侧说明统一 API 的产品价值，右侧展示基于当前公开配置生成的代码示例与非伪造状态。协议条、模型预览和文档入口必须在数据不可用或为空时降级为对应的真实状态，不能用虚构的模型、价格、余额或成功请求填充。

模型广场采用搜索与筛选头部、模型列表/卡片混合的自适应布局；模型标识、提供商、能力和价格层级清楚。开发文档采用阅读型主栏与目录/代码块布局，复制操作、调用地址与模型示例均保持现有真实数据约束。服务地区和法律页采用低干扰的阅读布局，法律正文突出版本内容与支持入口，而非营销视觉。

### 认证页面

认证页使用居中表单面板与简化的品牌/返回首页入口；背景保留非常弱的请求轨迹纹理。登录和注册的真实可用性、注册策略、校验、忙碌和错误反馈保持不变，视觉只负责强化字段层级和安全说明。

### 用户控制台

`ConsoleLayout` 采用 220–240px 侧栏、紧凑顶栏和独立的内容滚动区域。侧栏分为工作区与账户两组，当前项以低对比绿色表面和文字/图标共同标识；移动端收缩为现有可访问抽屉。

Dashboard 用余额、请求、Token、成功率四类指标卡与趋势区组织真实数据；请求日志与 API 密钥页使用统一的工具栏、筛选、表格、分页、空状态和局部错误区。钱包、设置页面使用两列或单列的表单/摘要面板；危险操作只出现在既有确认对话框的最终确认态。

## 设计系统与组件边界

运行时令牌仍集中在 `frontend/src/design/tokens.css`，采用原始色板、语义色和组件令牌三层；所有新增颜色仅在令牌文件定义。`global.css` 负责全局排版、滚动条、焦点、动效降级和容器规则。

保留并视觉升级现有 `Button`、`Input`、`FormField`、`Dialog`、`DataTable`、`Pagination`、Toast 与通用页面状态组件。新增的可复用表现层只限于：页面标题区、深色面板、状态徽标、筛选工具栏、指标卡、代码窗口与请求轨迹。业务页面组合这些组件，不重复定义颜色、圆角、阴影或交互状态。

中文正文优先使用系统中文无衬线字体（`PingFang SC` 等），Manrope 用于英文、数字和标题骨架；JetBrains Mono 只用于代码、请求 ID、模型 ID 与技术状态。所有可点击元素保留语义 HTML、悬停、焦点、按下、禁用和忙碌状态。

## 行为与可访问性约束

- 不改变现有路由、Portal API 边界、鉴权、表单校验、确认、复制、分页、搜索取消和敏感值保护逻辑。
- 继续满足 WCAG 2.2 AA：文本对比度、键盘焦点、可访问名称、对话框焦点管理、状态文本与 `aria-live` 均不得因视觉重构退化。
- 对加载、空数据、无结果、局部错误、无权限和未知结果保留稳定的几何尺寸；单一接口失败不应清空同页已成功数据。
- 表格仅在自身容器滚动；窄屏不出现页面级横向溢出。移动端导航、表格操作、筛选与对话框均可通过触摸和键盘访问。
- 动效以 160–220ms 的透明度/颜色变化为主；`prefers-reduced-motion` 下关闭所有装饰性动效。

## 实施方式

1. 建立 `DESIGN.md`，将上述视觉原则、令牌所有权和运行时映射沉淀为长期设计上下文。
2. 先升级令牌、全局样式、品牌、基础组件和三类布局，使所有路由自动获得新的表面、排版与可访问交互基线。
3. 依次重构公开内容页、认证页、控制台数据页与法律/异常页；每页仅使用真实数据和现有安全业务流程。
4. 扩充/修正现有组件与页面测试，执行静态检查、单元测试、构建及浏览器流程验证。

## 验收标准

- 所有现有前端路由呈现统一的 Deep Ink 品牌语言，且公开站与控制台密度明确不同。
- 首页符合已确认的中文主导 B2 分栏结构；代码终端与数据展示不暗示不存在的运行状态。
- API 密钥、请求日志、钱包、设置和认证流程保留现有业务、安全和无障碍行为。
- 320px 窄屏及桌面宽度均无页面级横向滚动，键盘可操作，减少动效偏好有效。
- `npm run lint`、`npm run test`、`npm run build` 及适用的 E2E/视觉检查通过。
