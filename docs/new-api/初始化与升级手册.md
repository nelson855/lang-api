# New API 初始化与升级手册（LANG-P1-02）

## 1. 首次初始化（受控运维入口）

```bash
cp deploy/.env.example deploy/.env
# 数据库与 Redis 密码会拼进连接地址，必须用链接安全字符：
openssl rand -hex 24
# SESSION/CRYPTO 密钥直接透传，可用：
openssl rand -base64 48
# 把生成的值分别填入 deploy/.env（base64 的 +/= 等符号曾导致数据库地址解析失败，已实测）

# 构建自研后端（构建容器内连不上公司内网 Maven 仓库；
# Compose 已改用项目自带的 deploy/maven-settings.docker.xml，经 secret 注入，不进镜像）
docker compose --env-file deploy/.env -f deploy/compose.yml up -d --build

# 临时打开本机回环管理入口
docker compose --env-file deploy/.env -f deploy/compose.yml -f deploy/compose.ops.yml up -d

# 在本机浏览器或 curl 访问 http://127.0.0.1:13000 完成管理员初始化
# 管理员凭证只保存在本地密钥管理位置，不入库、不进探测样例

# 撤销运维入口并验证端口消失、数据保留
docker compose --env-file deploy/.env -f deploy/compose.yml up -d
docker compose -f deploy/compose.yml ps
```

健康与初始化是两个判断：健康检查只判断服务可响应（New API 用 GET /api/status；
实测发现该接口不支持 HEAD，健康检查必须用 GET），初始化完成以 setup 接口/页面状态为准。

## 1.1 实测记录（2026-09-12，v0.13.2）

- 初始化前 `GET /api/setup` 返回 `{status:false,root_init:false,database_type:postgres}`。
- `POST /api/setup`（username≤12 字符、password 与 confirmPassword 一致且≥8 位）返回 `系统初始化成功`。
- 初始化后 `GET /api/setup` 返回 `{status:true}`；重复初始化返回 `系统已经初始化完成`。
- 删容器重建后状态与管理员登录均保留；`pg_dump` 备份恢复到隔离项目后状态与登录同样保留。
- 接口认证需同时携带会话 Cookie 与 `New-Api-User: <用户id>` 请求头，缺头即 401（后续 Portal 适配必须同时透传两者）。

## 2. 日常启动与停止（保留数据）

```bash
# 启动（重复执行收敛到相同拓扑）
docker compose --env-file deploy/.env -f deploy/compose.yml up -d --build
# 停止（保留卷）
docker compose -f deploy/compose.yml stop
# 删除容器但保留卷
docker compose -f deploy/compose.yml down
```

## 3. 彻底重置（独立章节，不可恢复警告）

> 警告：以下命令删除 PostgreSQL 命名卷与全部业务数据，不可恢复。执行前确认已备份。

```bash
docker compose -f deploy/compose.yml down -v
```

## 4. 数据持久化验收

1. 初始化后创建一个无真实个人信息的抽样对象，记录其稳定标识；
2. 执行不删除卷的停止与容器重建；
3. 再次查询初始化状态与抽样数据，确认仍存在且不再进入首次设置流程；
4. 仅看到卷存在不算通过。

## 5. 备份与恢复

```bash
# 备份（密码经环境传入，不回显；备份文件进入被忽略目录）
docker compose -f deploy/compose.yml exec -T -e PGPASSWORD="$POSTGRES_PASSWORD" postgres \
  pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" > ./backups/newapi-$(date +%F).sql

# 校验与保管：确认文件非空并记录校验和，存放在仓库外的受保护位置
ls -lh ./backups/ && shasum -a 256 ./backups/newapi-*.sql
```

## 6. 升级门禁（备份—副本迁移—复验—切换—失败恢复）

1. 记录当前镜像 digest 与数据库状态；
2. 用 `pg_dump` 生成受保护的本地备份；
3. 将备份恢复到隔离的数据库卷/Compose 项目；
4. 在副本上启动候选镜像，让 New API 自身执行 schema 初始化/迁移（本项目不编写或修改上游 SQL）；
5. 重跑兼容性探测与抽样数据核对；
6. 通过后才更新冻结记录与主 Compose digest；
7. 禁止仅修改 tag/digest 即宣布升级完成。

失败恢复：使用旧镜像与未迁移备份恢复，不让旧镜像直接连接已被新版本迁移的唯一数据库。
