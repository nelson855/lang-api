# New API 后台运维操作手册

操作对象：随项目 Compose 一起部署的 New API（`calciumion/new-api`，版本见
[基线版本与许可证](./基线版本与许可证.md)），负责模型渠道、密钥、用户额度等底层能力。
日常业务（查模型、调接口、管 Portal 密钥）走 Lang API 自己的前端和 Portal 接口；
只有配模型源、查底层数据、做初始化/升级时，才需要进 New API 后台。

## 1. 核心原则

- New API 的 3000 端口**平时不向任何机器开放**，主 Compose 文件（`deploy/compose.yml`）
  里它没有任何端口映射，只能在 Docker 内部网络里被访问。
- 管理入口按"用时打开、用完即关"处理，不长期保留。
- 管理员账号和密码只保存在本地密码管理工具里，不进仓库、不进文档、不进聊天记录。
- 任何改动先在本地/测试环境验证，再动生产。

## 2. 什么时候需要进后台

| 场景 | 说明 |
|---|---|
| 首次初始化 | 新环境第一次启动，创建 root 管理员（见第 4 节） |
| 配置模型源 | 新增/更换上游模型渠道、填密钥和地址、开关模型 |
| 渠道排障 | 上游报错、余额异常时看渠道测试结果和日志 |
| 用户与额度 | 手动查底层用户、订阅和剩余额度（日常以 Portal 为准） |
| 升级 | 按[初始化与升级手册](./初始化与升级手册.md)的备份—副本迁移流程走，不在本手册范围内 |

## 3. 本地/测试环境：运维入口叠加

适用于你本机或测试机，能直接在本机开浏览器。

```bash
# 打开入口（只绑本机回环，局域网其他机器够不着）
docker compose --env-file deploy/.env -f deploy/compose.yml -f deploy/compose.ops.yml up -d
```

```bash
# 用完关闭，并确认端口消失
docker compose --env-file deploy/.env -f deploy/compose.yml up -d
docker compose -f deploy/compose.yml ps
```

说明：

- `deploy/compose.ops.yml` 只做一件事：把 new-api 的 3000 映射到本机 `127.0.0.1:13000`
 （端口可用 `NEW_API_ADMIN_PORT` 环境变量改）。
- 打开和关闭都会重建 new-api 这一个容器（秒级，改端口映射必须重建容器），
  其他四个服务不动，不重新构建镜像，数据全在卷里。
- 浏览器打开 `http://127.0.0.1:13000`，登录 root 管理员操作。

## 4. 首次初始化（新环境）

1. 按第 3 节打开入口。
2. 浏览器访问 `http://127.0.0.1:13000`，会自动进入设置页。
3. 创建管理员：用户名不超过 12 个字符，两次密码一致且至少 8 位。
4. 初始化成功后可用接口复核（应返回已初始化）：

```bash
curl http://127.0.0.1:13000/api/setup
```

5. 按第 3 节关闭入口，确认数据保留（重建容器后再次打开，管理员登录仍有效）。

## 5. 生产环境：SSH 隧道（推荐）

生产机是无桌面的 Linux，不要在上面找浏览器，也不要给生产 Compose 加端口映射。
**所有命令都在你自己 Mac 的终端里敲，浏览器也用 Mac 的。**

```bash
# 在 Mac 终端执行：登录生产主机的同时，把远端的 new-api 3000 转到 Mac 本地的 13000
# 保持这个窗口别关
ssh -L 13000:localhost:3000 你的用户名@生产主机地址
```

然后在 Mac 浏览器打开：

```
http://127.0.0.1:13000
```

看到的就是生产机上 New API 的后台。用完把终端窗口关掉，隧道即断，
生产侧容器零变更、零重启、无新增对外端口。

只想查个简单状态不想开浏览器时，同样走这条隧道：

```bash
curl http://127.0.0.1:13000/api/setup
```

## 6. 在后台里配置模型源

登录后进**渠道管理**：

1. 新建渠道，选渠道类型（按上游实际类型选）。
2. 填上游地址、密钥、可调用的模型名列表。
3. 用渠道自带的测试功能验证连通，失败先看报错是地址、密钥还是模型名问题。
4. 启用渠道，回到 Lang API 侧用模型广场或文档页的真实请求复核一次。
5. 密钥轮换时：先建新渠道验证通过，再停用旧渠道，不要直接改在用渠道的密钥。

## 7. 收尾检查

每次操作完对照这三项：

- [ ] 运维入口已关闭（本地：`ps` 看不到 13000 映射；生产：SSH 隧道窗口已关）。
- [ ] Lang API 侧复核通过（模型列表、一次真实调用、日志里有记录）。
- [ ] 改了什么、为什么改，记到当天的变更记录里（改了哪个渠道、旧值去向）。

## 8. 常见问题

- **浏览器打不开 13000**：先确认隧道/叠加入口还在（SSH 窗口没关？`ps` 里 new-api 的端口映射还在？），
  再确认 new-api 容器是 healthy（`docker compose -f deploy/compose.yml ps`）。
- **登录报 401**：New API 接口认证要同时带会话 Cookie 和 `New-Api-User` 请求头，
  浏览器正常登录一般不会遇到；用脚本调接口时记得两个都带。
- **初始化页反复出现**：数据库卷可能被删过（`down -v` 会清数据），按[初始化与升级手册](./初始化与升级手册.md)
  第 3 节先确认是不是误执行了不可逆操作，再从备份恢复。
- **网关 502 但 new-api 是 healthy**：看网关和 lang-api 的日志，多半是上游渠道配置问题，
  回后台渠道管理做连通测试。
