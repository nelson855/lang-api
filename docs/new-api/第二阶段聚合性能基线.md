# 第二阶段聚合性能基线

基线版本：`p2-2026-09-22-a`。环境为本地 Docker Compose、New API v0.13.2、本机回环网络。

## 当前状态

本轮完成了功能性探测（六个接口各场景的真实调用与 fixture 固化），**不具备典型历史数据量及 24 小时、7 天、30 天各 20 次稳定测量的前置条件**。

因此**不发布** p50/p95、最大页数或容量外推结论。

## LANG-P2-02 保护边界建议

在获得足量数据前，下游聚合实现必须采用保守保护：

| 边界 | 建议值 | 说明 |
|---|---|---|
| 最大页数 | ≤ 10 页 / 次查询 | 基于典型 page_size=20，覆盖 200 条记录 |
| 最大记录数 | ≤ 200 条 / 次聚合 | 与最大页数一致 |
| 单次上游调用超时 | ≤ 5 秒 | 本机回环实测每次调用 < 1 秒，留 5 倍余量 |
| 聚合总超时 | ≤ 30 秒 | 覆盖多接口并行 + 少量串行重试 |
| 24 小时范围实时聚合 | 允许 | 日志量通常在保护边界内 |
| 7 天范围实时聚合 | 谨慎允许 | 若超出最大页数，降级为小时桶预聚合 |
| 30 天范围实时聚合 | 默认禁用 | 除非实测验证，否则强制走预聚合 |

## 需要单独评估的触发证据

若后续实测发现以下任一情况，**必须单独评估**预聚合存储或缓存策略：

1. 30 天实时聚合的 p95 延迟超过 5 秒
2. 单次 30 天查询需要超过 50 页日志分页
3. 单用户月度日志量超过 10 万条
4. New API 上游对长时间范围查询返回 5xx 或截断响应

## 历史数据不足声明

本基线**不外推**：当前 sample 数据量（9 条日志）不构成生产容量规划依据。LANG-P2-02 应：
- 初期使用保守保护边界上线
- 在生产环境积累真实数据后，重新执行性能探测
- 若需调整保护边界，作为显式兼容性变更重新验证
