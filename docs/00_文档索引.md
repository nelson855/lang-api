# Lang API 项目文档索引

本目录保存 Lang API 聚合平台的产品与技术指导文档。当前目标不是复刻某个站点，也不是重写 New API，而是在复用其成熟能力的基础上，建立独立的用户产品和公开接口表面。

## 文档顺序

1. [项目背景、目标与总体架构](./01_项目背景目标与总体架构.md)
   - 项目总纲；定义为什么开发、什么算成功、哪些事情不做，以及总体架构边界。
2. [QinghuaAPI 与 New API 功能对比](./02_青花API与NewAPI功能对比.md)
   - 产品范围；逐项说明直接复用、基于底层数据实现和必须二次开发的内容。
3. [实施顺序与 Portal API 蓝图](./03_实施顺序与Portal接口蓝图.md)
   - 交付路线；规定三个实施阶段、接口命名、验收条件和升级约束。
4. [QinghuaAPI 只读调研原始记录](./99_青花API只读调研原始记录.md)
   - 调研附录；用于追溯参考站点中实际确认和未确认的内容。

## 决策优先级

出现冲突时，按以下顺序处理：

1. 用户在当前对话中明确提出的新要求；
2. [项目背景、目标与总体架构](./01_项目背景目标与总体架构.md)中的目标与边界；
3. [实施顺序与 Portal API 蓝图](./03_实施顺序与Portal接口蓝图.md)中的阶段划分；
4. 参考站点的具体表现。

QinghuaAPI 只是功能参考，不是视觉规范，也不是必须兼容的 API 契约。
