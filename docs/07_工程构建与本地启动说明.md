# 工程构建与本地启动说明（LANG-P1-01 工程基线）

## 1. 正式构建命令（唯一入口）

```bash
/Users/nelson/software/apache-maven-3.8.4/bin/mvn -s /Users/nelson/software/apache-maven-3.8.4/conf/settings.xml clean package
```

- 必须带 `-s` 指向项目指定的 `settings.xml`，不要用默认 `~/.m2`。
- 本地仓库固定为 `/Users/nelson/software/apache-maven-3.8.4/repository`（见 `settings.xml`）。
- 单条命令完成：前端依赖安装 → 前端检查与测试 → 前端生产构建 → 后端编译与测试 → 静态资源装配 → 可执行 JAR 打包。
- 任何一步失败，整条构建失败，不产出可发布制品。

## 3. 环境 Profile 的选择方式

共享配置在 `application.properties`，不默认激活任何环境。每次启动必须显式指定：

```bash
# 本地开发
java -jar portal-api/target/portal-api-0.1.0-SNAPSHOT.jar --spring.profiles.active=dev

# 生产（容器内默认，见 Dockerfile 的 SPRING_PROFILES_ACTIVE=prod）
SPRING_PROFILES_ACTIVE=prod java -jar portal-api/target/portal-api-0.1.0-SNAPSHOT.jar

# 自动化测试固定使用 test（测试类已用 @ActiveProfiles("test") 声明）
```

敏感值（密钥、真实地址）一律由环境变量或外部 `.properties` 覆盖，仓库文件只放占位与安全默认值。

## 4. 前后端分开编译与启动（日常开发）

正式提测与发布永远走第 1 节的统一入口。下面命令只用于日常开发提速，改完后仍要跑一次统一构建确认。

### 前端单独（在 `frontend/` 目录下执行）

```bash
cd frontend
npm ci                  # 严格按 package-lock.json 安装依赖
npm run dev             # 开发服务器，默认 http://localhost:5173，改完即时生效
npm run lint            # 类型检查与代码规范
npm run test            # 跑单测（非监听模式）；监听模式用 npm run test:watch
npm run build           # 生产构建，产物在 frontend/dist
```

- 本机 Node 是 v23.11.0，与锁定的 v22.17.0 不一致时如果遇到怪问题，可改用构建插件装好的 `./node/node --version` 先确认版本是否正常。
- 基线阶段前端没有接口调用，不需要配代理；开发服务器只提供前端页面，路由回退与接口行为以实际后端和统一构建为准。

### 后端单独（在仓库根目录执行，`-pl portal-api` 表示只选后端模块）

```bash
# 只跑后端测试
/Users/nelson/software/apache-maven-3.8.4/bin/mvn -s /Users/nelson/software/apache-maven-3.8.4/conf/settings.xml -pl portal-api test

# 只打后端包（复用已有的 frontend/dist，不重跑前端构建；
# 如果从没跑过统一构建导致 dist 缺失，会被构建校验明确拦下）
/Users/nelson/software/apache-maven-3.8.4/bin/mvn -s /Users/nelson/software/apache-maven-3.8.4/conf/settings.xml -pl portal-api package

# 后端开发启动（默认 8080 端口，dev 环境，改完 Java 代码自动重启不生效，需重跑）
/Users/nelson/software/apache-maven-3.8.4/bin/mvn -s /Users/nelson/software/apache-maven-3.8.4/conf/settings.xml -pl portal-api spring-boot:run -Dspring-boot.run.profiles=dev
```

- 后端包里看到的前端页面，来自上一次前端构建的 `frontend/dist`；改了前端要看效果，先跑 `npm run build` 或直接跑统一构建。
- 生产包的验证仍然用第 3 节的 `java -jar … --spring.profiles.active=…` 方式。

## 5. 容器构建与运行

```bash
# 构建（Maven 私服凭据经 BuildKit secret 注入，不进镜像）
DOCKER_BUILDKIT=1 docker build \
  --secret id=maven_settings,src=/Users/nelson/software/apache-maven-3.8.4/conf/settings.xml \
  -t lang-api:0.1.0 .

# 运行
docker run -d --name lang-api -p 8080:8080 lang-api:0.1.0

# 检查：非 root 身份、健康检查、无构建工具
docker exec lang-api whoami
curl -s http://127.0.0.1:8080/actuator/health
docker exec lang-api sh -c 'command -v node; command -v npm; command -v mvn; ls /app'
```

## 6. 验证点速查

- 根路径 `/` 返回 React 入口页；`/dashboard` 刷新同样返回入口页（客户端路由回退）。
- 未知 `/portal/api/*` 返回 JSON 404；未知 `/actuator/*` 与缺失静态文件不回退页面。
- `/actuator/health` 返回 `{"status":"UP"}` 且不含密钥；`/actuator/info` 可见 `lang-api` 与 Maven 版本。
- `git status` 只出现源码与配置新增；`frontend/dist`、`target/` 等生成物不进版本库。

## 7. 常见问题

- 构建插件在 `install-node-and-npm` 失败，且 `frontend/node` 下只剩残缺目录：
  先删掉本机工具链缓存再重跑正式构建（不影响源码，Node 会从本地 Maven 仓库解压恢复）。
  ```bash
  rm -rf frontend/node frontend/node_modules
  /Users/nelson/software/apache-maven-3.8.4/bin/mvn -s /Users/nelson/software/apache-maven-3.8.4/conf/settings.xml clean package
  ```
