# LANG-P1-05 认证与会话闭环

## 对外接口

- `GET /portal/api/auth/options`：返回公开注册开关，以及固定关闭的邮箱验证、验证码能力。
- `GET /portal/api/auth/csrf`：签发一次同源双提交 CSRF Token。
- `POST /portal/api/auth/register`、`/login`、`/refresh`、`/logout`：所有写操作都要求 CSRF Cookie、Header 与允许的 Origin。
- `GET /portal/api/profile`：返回最小 profile（id、username、displayName、email），不返回角色、上游 Cookie 或长期令牌。

## 生产运维

- 生产默认关闭公开注册；仅设置 `PORTAL_REGISTRATION_ENABLED=true` 才会开启。关闭时由管理员在受控 New API 私网后台预建账号。
- 必须提供 `PORTAL_ALLOWED_ORIGINS` 和 `PORTAL_TRUSTED_PROXY_CIDRS`；只信任该 CIDR 内代理转发的客户端地址。
- 会话使用 Host-only、`HttpOnly` 的 `LANG_SESSION` 与 `LANG_UID`，Path 为 `/portal`，SameSite 为 `Lax`，生产必须 `Secure=true`；不支持 Cookie Domain 配置。
- 限流为单实例内存固定窗口。水平扩容前不能将它视为全局限流，应在后续变更中引入共享限流设施。

## 回滚与验收

- 本变更不写入 Portal 数据库；回滚无需数据迁移。已创建的账号仍由 New API 管理。
- 回滚或切换到不识别这两个 Portal Cookie 的版本后，用户必须重新登录。
- 发布前执行指定 Maven `verify`、前端单测、Lint、生产构建及 Playwright 流程；同时扫描源码和构建产物，确认不含私网地址、上游管理路径、上游 Cookie 名或长期浏览器凭证。
