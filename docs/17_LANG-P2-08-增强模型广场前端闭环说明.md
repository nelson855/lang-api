# LANG-P2-08 增强模型广场前端闭环说明

本文件说明模型广场（`/models`）与公开模型详情页（`/models/:modelRef`）的前端闭环实现，覆盖详情引用、URL 状态、厂商加载、一致性策略、价格精度、缺失字段表达、文档联动与验证结果，并单独记录仍未解除的外部阻塞。

后端接口契约不在本文件范围内，见 [LANG-P2-07 模型详情与供应商筛选接口说明](16_LANG-P2-07-模型详情与供应商筛选接口说明.md)。本次改动不修改后端接口、计费换算、缓存策略或公共配置。

## 1. 模型详情引用

公开详情路由为 `/models/:modelRef`，`modelRef` 遵循与后端 `ModelRef` 相同的规则：原始模型 ID 的 UTF-8 字节经网址安全 Base64 无填充编码。

前端实现在 `frontend/src/features/catalog/modelRef.ts`，与后端保持同一套拒绝条件：

- 只接受 `[A-Za-z0-9_-]`，拒绝空值、`=` 填充与非法字母表字符；
- 使用 `TextDecoder('utf-8', { fatal: true })` 严格解码，拒绝非法 UTF-8；
- 解码后重新编码，要求与输入完全一致，拒绝非规范重编码；
- 校验目录编号边界：非空、长度 1~128、无控制字符（`≤ 0x1F` 与 `0x7F`）。

解码结果不裁剪、不折叠大小写、不做 Unicode 归一化。含 `/`、`%`、空格、中文与表情的编号编码后仍是单一路径段。

非法引用在发送详情请求前即被拦截：页面显示安全参数错误与返回模型广场入口，不回显解码内容。相关路由与 API 路径构造集中在 `frontend/src/features/catalog/catalogPaths.ts`，只从原始 ID 生成路径，不接受显示名、厂商名或规范化 ID。

详情只使用与引用匹配的成功响应。响应中的 `model.id` 与解码 ID 不一致时按契约错误处理（`resolveDetailModel` 返回空），页面不会展示另一个模型。404 显示模型不存在或已下架，上游失败提供安全重试。已有成功缓存的详情再次请求失败时隐藏旧模型信息、价格及操作入口，不将缓存旧数据作为当前成功结果展示。模型切换时查询键随路由变化，旧响应写入自己的缓存键，不会覆盖新页面。

## 2. URL 状态

列表与详情使用同一组受控条件：`?q=<search>&provider=<value>`。适配层在 `frontend/src/features/catalog/catalogUrlState.ts`：

- 白名单参数只有 `q` 与 `provider`，未使用的参数既不参与筛选也不被序列化回写；
- 重复参数取首个；
- 搜索忽略首尾空白，厂商保持大小写敏感的精确名称；
- 空参数一律省略；
- 搜索输入替换当前历史项（`replace`），厂商的明确选择形成历史项（`push`）；
- 输入法组合期间不触发导航，`compositionend` 时一次性同步搜索条件；
- 清除操作立即更新结果并把焦点交回输入框。

刷新、分享、直接进入与浏览器前进后退都能恢复相同条件。详情链接携带当前条件，"返回模型广场"使用受控同源路径 `/models?q=…&provider=…` 重建条件，不依赖必须存在的浏览器历史，也不接受可执行的 `returnTo`。

URL 中的未知厂商保留为可清除条件，并显示筛选无结果：页面不伪造 Select 选项，也不静默展示全部模型。

## 3. 厂商选项加载

厂商筛选项来自 `GET /portal/api/model-providers` 的 `value`、`label` 与 `modelCount`，不再从模型数组派生，也不使用静态品牌表。计数表达完整目录数量，而不是当前搜索命中数。

列表与供应商并行加载，各自保留 loading / error / success：

- 列表失败停止目录展示，显示安全错误与重试；
- 供应商失败保留已加载的列表、搜索与 URL 现存条件，厂商控件标记为暂不可用并单独重试，不从模型数组生成替代选项；已有厂商条件始终提供独立清除按钮，不依赖供应商加载成功；
- 成功的空供应商数组不是错误状态。

搜索与筛选都在已取得的完整目录上本地执行，不为每次输入或选择新增目录请求。列表不为完整卡片逐个拉取详情，避免 N+1 请求。

## 4. 跨响应一致性

判定逻辑在 `frontend/src/features/catalog/catalogConsistency.ts`。

厂商选项只有在以下条件同时成立时才启用：两次成功响应的非空 `pricingVersion` 相同，且供应商名称与完整计数能与当前列表核对通过。计数核对使用全部模型，不使用搜索过滤结果。

其余情形：

| 情形 | 行为 |
|---|---|
| 已知版本不同 | 暂停使用冲突选项，强制对列表与供应商成对重取一轮；仍冲突则停止自动请求，展示冲突状态与手动重试 |
| 任一版本为 null | 标记为无法确认跨请求版本一致性；结构核对通过仍可提供筛选，并给出简短提示 |
| 已知版本相同但结构对不上 | 按冲突处理，不启用错项 |
| 列表中的未知厂商 | 不伪造进选项，也不归入"其他" |

自动恢复最多执行一轮，由 `conflictRetried` 与 `recoveryStartedRef` 共同约束，不由 render 或 useEffect 无限触发。手动重试开启新一轮有界恢复。

从列表进入详情时，详情页会订阅缓存中的列表版本：只有缓存里已有列表时才做对照，已知版本冲突时对列表与详情成对重取一轮；重取后仍冲突则停止自动请求，页面继续展示详情自身完整成功响应并提示"暂时无法与目录对照版本一致性"，同时提供手动成对重取入口；恢复期间按钮禁用，防止重复触发。自动恢复次数按当前模型引用记录，切换模型后允许新模型执行一轮恢复。直达详情只请求详情接口，缺少列表不构成错误，也不为一致性强制加载列表。

详情的基本信息与价格全部来自同一次成功详情响应，不拼接缓存列表价格与新详情元数据。

## 5. 价格精度

价格展示规则集中在 `frontend/src/features/catalog/priceFormat.ts`，列表与详情共用。

- 全程使用十进制字符串，不调用 `Number`、`parseFloat` 或 `toFixed`，不做前端换算、不使用硬编码倍率、不静默舍入；
- 科学计数法用字符串算法展开（如 `1.5e-7` 规范展示为 `0.00000015`），保留接口给出的完整精度；
- 真实零价展示为零而不是缺失；
- `pricing = null` 显示价格暂不可用，不解释为免费；
- TOKEN 按每百万 Token 的美元计，REQUEST 按每次请求的美元计，字段与单位组合严格遵循现有契约；
- 增强价格沿接口给出的币种与单位展示，币种来自每个价格项，不复用基础价格的 USD；`unit` 未知时也保留币种与接口单位原文，不猜测换算；
- 增强金额按接口合法十进制语义校验，接受普通小数和科学计数法，不套用基础价格最多 6 位小数的限制。

基础价格是目录参考价，页面明确区分参考价与最终实际扣费；目录可用性不承诺任一 Key 可调用。

## 6. 缺失字段表达

展示规则在 `frontend/src/features/catalog/metadataDisplay.ts`，`null`、`false`、已验证空集合与合法数值零各自独立分支：

| 接口值 | 页面表达 |
|---|---|
| `null` | 本地化"暂无数据" |
| `false` | "不支持" |
| `true` | "支持" |
| `[]` | "无"（标签为"无标签"） |
| 合法数值 `0` | 保留为零 |

四项能力始终可发现并各自独立展示，不使用真值判断把 `false` 与 `null` 合并。发布日期按日历日期展示，不作为 UTC 时间点转换，避免跨时区偏移一天。描述与标签作为文本渲染，不执行接口提供的 HTML。`sortOrder` 只属于可空排序元数据，列表保持服务端顺序，不构造"推荐"标签。

已验证空增强价格数组显示“暂无增强计费项目”，不使用未知价格说明。英文空模态集合显示 `None`，不使用中文默认值。

在当前冻结基线下，上下文窗口、最大输出、输入/输出模态、四项能力、发布信息、描述、标签与增强价格全部为 `null`：页面各信息区展示暂无数据并保持可用布局，不展示推测能力或静态默认参数。

## 7. 复制与文档联动

列表与详情共用 `frontend/src/features/catalog/CopyModelId.tsx`，只复制原始模型 ID，不复制 modelRef、显示名或厂商名称。复制成功与失败都提供可被辅助技术感知的反馈；剪贴板缺失或被拒绝时就地提示失败，并保留可选中的完整 ID 供手动复制，不使用浏览器 `alert`。

文档入口导航到 `/docs?model=<编码后的原始 ID>`。`DocsPage` 的模型选择逻辑已按规格修正：区分参数缺失与参数显式为空；显式 ID 必须精确存在于当前目录，否则展示"所选模型不可用"或"模型参数不合法"并提供返回模型广场入口，不静默替换为其他模型，也不生成冒充所选模型的示例。只有未指定 `model` 参数时才保留按 ID 排序选择首个可用模型的既有规则。示例模板、Base URL、协议范围与 Key 占位符未做改动。

导航一律使用 `Link`，不使用按钮模拟链接。

## 8. 路由与页面外壳

- `/models/:modelRef` 为独立懒加载路由，复用 `PublicLayout`；
- 路由元信息对该模式作明确匹配（`metaForPath` 中的单层路径规则），多层路径与未知路径仍按未找到处理；
- 详情不新增顶级导航项，公开导航仍只有模型广场入口；
- 页面标题与描述通过 `usePageChrome` 更新，导航后以标题公告新页面；
- 详情页按"模型标识与操作 → 基础价格 → 限制与模态 → 能力 → 发布信息与标签 → 增强计费"组织，元数据使用语义描述列表。

## 10. 当前外部缺口

本轮只交付当前基线可支持的前端闭环，以下阻塞**仍然存在**，未因本次改动解除：

- 上下文窗口、最大输出 Token、输入/输出模态、四项能力、发布信息、描述、标签与排序的可信来源仍缺失，接口继续返回 `null`；
- 增强计费项目（缓存、图片、音频、视频、搜索）仍无当前渠道的接口契约与计费单位证据，`enhancedPricing` 继续为 `null`；
- 基础价格换算所需的 `quotaPerUsd` 独立证据仍未取得（P2-01 遗留），目录价格仅供展示，不承诺最终扣费；
- 因此 `docs/11_第二阶段聚合能力开发与子需求拆分.md` 中 P2-08 的增强来源部分保持受阻，不将本次前端闭环完成视为增强字段已验证。

后续若上游提供可信的增强字段来源，只需补充接口契约与取证，前端展示规则与页面结构无需重新设计。
