# QinghuaAPI 与 New API 功能对比

## 1. 对比目的与依据

本文件用于回答三个问题：

1. 用户产品需要哪些功能；
2. 哪些功能可以直接复用 New API；
3. 哪些功能需要聚合计算或二次开发。

对比依据包括：

- QinghuaAPI 公开页面与前端资源；
- 测试账号下的控制台截图；
- QinghuaAPI 前端实际声明的 `/portal/api/*` 接口；
- New API 提交 `bdef117505247769268b209665fb3ad7554c3da7` 的路由、控制器和前端调用代码。

QinghuaAPI 是功能参考，不是 UI 设计稿。最终页面必须采用独立的结构、视觉和文案。

## 2. QinghuaAPI 已确认的用户功能

### 2.1 数据概览

- 时间范围：1H、24H、今天、昨天、7D、30D；
- 指标：请求总数、Token 用量、消费总额、活跃 Key、成功率、平均延迟；
- 图表：请求趋势、消费趋势；
- 最近请求入口。

### 2.2 API Keys

- 展示 OpenAI、Anthropic、Gemini 三类 Base URL；
- 搜索名称或 API Key；
- 按状态筛选；
- 列表字段：名称、掩码 Key、过期时间、最后使用、额度限制、状态；
- 支持显示/隐藏、复制、启停和更多操作；
- 支持创建 API Key。

创建和编辑弹窗没有作为本项目硬性参考。第一阶段直接采用 New API 已支持的字段，再由本项目重新设计交互。

### 2.3 请求明细

- 筛选：令牌、模型、状态、时间范围；
- 时间范围：1H、24H、今天、昨天、7D、30D；
- 列表字段：请求 ID、时间、令牌名称、模型、协议类型、状态、输入、输出、耗时、首字延迟、费用。

截图账号没有真实请求，因此详情抽屉及异常记录表现尚未确认。本项目不依赖其细节，可以直接以 New API 日志字段为第一版基础。

### 2.4 我的钱包

- 指标：可用额度、充值余额、选定时间范围内的消费总额；
- 可用额度口径：充值余额加剩余信用额度；
- 筛选：交易类型和时间范围；
- 交易表字段：时间、类型、金额、备注、明细；
- 提供充值入口。

### 2.5 个人设置

- 用户名；
- 邮箱，可选；
- 手机号，可选；
- 新密码和确认新密码；
- 保存修改。

### 2.6 公开产品

- 营销首页；
- 模型广场；
- 开发文档；
- 登录与注册；
- 服务条款、隐私政策和支持地区；
- 中文和英文界面。

## 4. 能力分类

### 4.1 A 类：New API 已完全或基本具备，第一阶段优先

“基本具备”表示业务动作和主要数据已存在，允许第一版沿用 New API 字段，不为匹配 QinghuaAPI 而延迟上线。

| 用户能力 | New API 能力 | 第一阶段处理 |
|---|---|---|
| 登录、注册、退出、刷新会话 | `/api/user/login`、`/api/user/register`、`/api/user/auth/*` | Portal API 改名并适配 Cookie、Token 和错误结构 |
| 当前用户资料 | `GET /api/user/self` | 字段裁剪后返回 |
| 修改用户资料与密码 | `PUT /api/user/self` | 直接适配；前端按 New API 实际约束设计 |
| API Key 列表与详情 | `GET /api/token/`、`GET /api/token/{id}` | 转换分页和字段名 |
| API Key 创建、编辑、删除 | `POST/PUT /api/token/`、`DELETE /api/token/{id}` | 直接适配 |
| API Key 启停 | `PUT /api/token/?status_only=true` | 映射为独立语义接口 |
| Key 额度、过期、模型和 IP 限制 | New API Token 数据模型 | 第一版可全部保留，前端可先只展示必要字段 |
| 请求日志列表 | `GET /api/log/self` | 映射时间、模型、Token、状态和分页参数 |
| 请求用量基础统计 | `GET /api/log/self/stat`、`GET /api/data/self` | 第一版按现有口径展示 |
| 用户额度 | `GET /api/user/self` 中的 quota | 转换为产品显示金额 |
| 充值配置和支付入口 | `/api/user/topup/info`、各支付接口 | 只适配已启用的支付方式 |
| 充值记录 | `GET /api/user/topup/self` | 映射为充值记录 |
| 模型与基础价格 | `GET /api/pricing` | 第一版直接使用 New API 的模型、厂商、倍率和计费信息 |
| 用户协议 | `GET /api/user-agreement` | 对外包装为本项目路径 |
| 隐私政策 | `GET /api/privacy-policy` | 对外包装为本项目路径 |
| OpenAI/Anthropic/Gemini 等模型调用 | New API Relay 路由 | 通过独立模型 API 域名白名单转发 |
| New API 管理功能 | New API 默认管理后台 | 私网原样使用，不自研管理前端 |

### 4.2 B 类：New API 有底层数据，第二阶段实现

| 目标功能 | 可用底层数据 | 为什么不能简单直出 | 建议实现 |
|---|---|---|---|
| 概览六项指标 | 用量聚合、请求日志、Token 数据 | 没有完全匹配的用户端综合接口 | Portal API 形成单一 dashboard 接口 |
| 请求趋势和消费趋势 | `/api/data/self` 中的小时数据 | 返回结构和页面目标不同 | 按时间粒度分桶并缓存 |
| 活跃 Key | 用量记录中的 Token ID | 缺少按时间范围去重后的直接值 | 统计时间范围内不同 Token ID |
| 用户成功率 | 消费日志和错误日志 | New API 用户统计接口不直接返回完整成功率 | 定义成功口径后聚合 |
| 用户平均延迟 | 请求日志 `use_time` 等字段 | 缺少用户维度综合聚合接口 | 在服务端按时间范围聚合 |
| 最近请求 | `/api/log/self` | 只需字段裁剪 | Dashboard 接口返回最近若干条 |
| 钱包消费总额 | 日志 quota 和用量统计 | 需要统一换算币种和时间范围 | 统一金额转换后聚合 |
| 钱包统一交易流水 | 充值记录、消费/退款日志 | 数据分散且类型不同 | 合并为只读流水视图 |
| 请求协议类型 | 请求路由和日志扩展信息 | 默认日志字段不一定直接提供目标展示值 | 映射端点类型或补充记录 |
| 首字延迟 | 日志扩展数据可能具备 | 字段和覆盖范围需要实测 | 有数据则显示，无数据返回 null |
| 模型广场增强 | `/api/pricing`、模型元数据、厂商数据 | 价格和展示元数据结构不同 | 合并、缓存并形成稳定模型目录接口 |

第二阶段禁止通过“拉取所有分页日志到前端再计算”实现正式统计。数据量小时可以临时验证，但生产实现应由 Portal API 聚合，并在需要时增加缓存或小时统计表。

### 4.3 C 类：New API 不具备或不足，第三阶段二次开发

| 功能 | 缺口 | 建议 |
|---|---|---|
| 独立开发者条款 | New API 只有用户协议和隐私政策 | 增加自有法律文档类型 |
| 支持地区政策 | 无独立内容模型 | 加入法律内容服务或公开配置 |
| 法律文档版本 | 只有正文字符串 | 增加 version、effective_at、content_hash |
| 用户协议同意记录 | 无完整版本化同意审计 | 记录用户、版本、时间、IP、User-Agent |
| 条款更新后重新同意 | 无版本状态机 | 对重大版本设置强制重新同意 |
| QinghuaAPI 风格的完整模型目录 | 上下文、发布日期、模态、能力等信息可能不完整 | 建立自有模型展示元数据 |
| 独立信用额度体系 | New API 主要是 quota 模型 | 只有业务明确需要授信时再开发 |
| 完整独立账务总账 | New API 额度和日志足够第一版，但不是自有财务总账 | 收入和用户规模证明必要性后建设 |

## 5. 页面范围与阶段

| 页面 | 第一阶段 | 第二阶段 | 第三阶段 |
|---|---|---|---|
| 首页 | 独立静态页面 | 运营配置可选 | CMS 可选 |
| 模型广场 | New API 基础价格列表 | 增强筛选和模型展示元数据 | 独立模型目录维护 |
| 开发文档 | 自有静态文档 | 文档搜索、版本 | 在线调试等增强能力 |
| 登录/注册 | New API 能力适配 | OAuth/MFA 按需 | 协议版本同意流程 |
| 数据概览 | 先展示 New API 可直接提供的数据 | 六指标、趋势和最近请求聚合 | 高级分析 |
| API Keys | 完整交付 | 批量操作等增强 | 无计划重写底层 |
| 请求明细 | New API 日志字段版 | 协议、TTFT、费用等增强 | 长期归档或导出 |
| 我的钱包 | 余额、充值入口、充值记录 | 消费汇总和统一流水 | 独立总账或授信体系 |
| 个人设置 | New API 当前用户字段 | 安全设置按需 | 自有扩展资料 |
| 法律页面 | 用户协议和隐私政策 | 内容接口统一 | 版本、历史和同意审计 |

## 6. 不采用的实现方式

- 不复制 QinghuaAPI 的页面布局、组件细节和视觉样式；
- 不让浏览器直接请求 New API 管理接口；
- 不在第一阶段维护第二套用户、额度或 API Key 数据；
- 不为了展示一个暂时没有的数据而伪造指标；
- 不把 New API 原始错误和内部字段原样返回公网；
- 不在公网开放 New API 默认管理后台。
