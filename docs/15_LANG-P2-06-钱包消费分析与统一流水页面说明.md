# LANG-P2-06 钱包消费分析与统一流水页面说明

`/dashboard/wallet` 在同一自然滚动页面中区分三种时间语义：当前权威余额、所选范围消费、历史统一流水，并保留充值关闭说明与既有充值记录独立兼容区。页面只做只读组合展示，不合并数据源、不推算金额、不新增任何资金操作入口。

## 页面结构

```text
钱包标题 + 数据性质说明（只读账户活动，非银行账单/发票）
┌ 当前余额（/portal/api/account/balance，不随筛选变化） ┐
│        ↓ 细路由轨迹（ledger rail，装饰性）              │
├ 范围工具栏 + 范围内消费汇总                            ┤
│        ↓ 同一范围                                      │
├ 类型工具栏 + 统一流水                                  ┤
└ 充值未开放说明 + 既有充值记录（独立来源，独立分页）    ┘
```

- 当前余额只来自余额接口；范围消费只来自消费汇总接口；统一流水只来自统一流水接口；既有充值记录只来自旧充值记录接口。任一区域失败只影响本区域，其他成功区域保留并可独立重试。
- 统一流水中的 `TOPUP`/`REFUND` 筛选项仅用于只读筛选，不是充值、退款、提现或争议处理入口。页面无金额输入、支付按钮、退款、提现或其他写控件。

## URL 参数（已提交状态唯一来源）

白名单参数：`range`、`startTime`、`endTime`、`timezone`、`granularity`、`type`、`page`。`pageSize` 固定 20，不进入 URL；`userId`、`requestId`、金额等敏感信息不进入 URL。

- 首次进入（无参数）用单次时钟快照生成 24H/`ALL`/第 1 页并 `replace` 写回完整 URL。
- 刷新、前进、后退复用 URL 原边界，不重新取时钟；重试调用当前查询的 `refetch`，不重建边界。
- 非法、缺半、矛盾参数回退安全默认并 `replace`；规范化完成前聚合查询保持 disabled。
- 切换范围生成新边界并重置页码；切换类型保留范围并重置页码；翻页只改页码。
- 响应 `total` 使当前页越界时 `replace` 收敛到最后有效页。

## 范围 preset

| preset | 范围 | 粒度 | 当前可请求 |
|---|---|---|---|
| `24h` | 当前时刻向前 24 小时 | `HOUR` | 是 |
| `today` | 用户时区今日 00:00 至当前 | `HOUR` | 是 |
| `yesterday` | 用户时区上一自然日 | `HOUR` | 是 |
| `7d` | 当前时刻向前 7×24 小时 | `HOUR` | 是 |
| `30d` | 当前时刻向前 30×24 小时 | `DAY` | 否 |

`30d` 在当前 P2-05 七天实时保护边界下可发现但不可选；即使 URL 直接携带 `30d`，页面也不向两个 P2-05 接口发送请求，仅展示阻塞原因。范围算法复用与 Dashboard 共享的中性聚合范围内核（秒级截断、IANA 校验、夏令时感知）。

## 接口归属

| 区域 | 接口 | 查询键 |
|---|---|---|
| 当前余额 | `GET /portal/api/account/balance` | 用量命名空间 + 用户 + `balance` |
| 范围内消费 | `GET /portal/api/account/consumption-summary` | 钱包命名空间 + 用户 + 完整范围 |
| 统一流水 | `GET /portal/api/account/transactions` | 钱包命名空间 + 用户 + 完整范围 + 类型 + 页码/页大小 |
| 充值能力 | `GET /portal/api/account/topup-options` | 钱包命名空间 + 用户 + `options` |
| 既有充值记录 | `GET /portal/api/account/topups` | 钱包命名空间 + 用户 + 页码/页大小 |

汇总与流水并行独立请求，关闭自动重试，透传 `AbortSignal` 由查询层取消迟到响应；旧范围、旧类型、旧页的迟到数据不覆盖当前界面。任一只读请求返回 `UNAUTHENTICATED` 即走统一会话失效，清除认证、用量、钱包（含汇总与流水）用户作用域缓存；普通区域失败不清除其他成功数据。

## availability / coverage 展示

- `AVAILABLE` 显示真实值（含零）；`UNAVAILABLE` 显示“暂不可用”及本地化原因，不显示为零或破折号假金额；`PARTIAL` 显示可用值并持续展示逐来源说明。
- 只有 `AVAILABLE + total=0` 才是真实空；`TOPUP`/`REFUND` 不可用即使 `items=[]` 也显示阻塞说明。
- 当前基线下：正式货币金额固定不可用（`CURRENCY_CONVERSION_NOT_VERIFIED`，不读 catalog 换算）；`TOPUP` 不可用（`BASELINE_NOT_VERIFIED`）；`REFUND` 不可用（`SOURCE_NOT_AVAILABLE`）；缺稳定引用的消费计入汇总但不进入流水（`PARTIAL + MISSING_STABLE_REFERENCE`）。
- 金额字符串不经 JavaScript `number`，按活动 locale 分组后直接展示；`QUOTA` 配 quota 单位，`CURRENCY` 配服务端给出的币种代码，不补算 USD。方向用文字加形状双重表达，不依赖颜色或正负号。时间按活动 locale 与响应时区格式化，同时保留原始 ISO。

## 响应式

桌面端统一流水使用语义表格（表头列作用域），横向溢出收敛在表格容器内；窄屏（≤640px）切换为等价卡片，重复全部标签与值，保持排序、coverage、分页与重试能力。页面整体自然滚动，无固定视口高度。

## 失败恢复

各区域独立 pending/error/success 分支与重试按钮；会话失效不展示局部错误；离线时已成功区域保留，失败区域提供显式重试，不自动重放。未知枚举与矛盾响应映射为通用数据失败面板，不输出原始错误。

## 安全边界

- 不接受 `userId`、`baseline`、客户端多类型、未知参数或上游原始字段；身份只取自服务端会话。
- 不把统一流水描述为银行账单、正式发票或完整会计凭证；不把旧充值记录并入统一流水；不用旧记录提升 `TOPUP` coverage。
- 支付能力关闭（`enabled=false`、失败或不支持的配置）时仅展示不可操作说明。
