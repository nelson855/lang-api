# aggregation-data-baseline Specification

## Purpose

为第二阶段所有服务端聚合能力建立可验证、可版本化的数据来源与计算口径基线，使指标、流水、时间和金额契约只依赖冻结版 New API 的真实证据，而不依赖字段名称猜测或浏览器端推算。

## Requirements

### Requirement: 聚合数据来源具有字段级证据
项目 SHALL 为 `/api/log/self`、`/api/log/self/stat`、`/api/data/self`、`/api/user/self`、`/api/user/topup/self` 和 `/api/pricing` 建立字段级来源矩阵。每个可能被第二阶段使用的字段 MUST 记录接口、JSON 路径、业务含义、类型、单位、可空性、时间或金额语义、适用日志类型、实测样例引用与结论状态；结论状态只允许使用 `已验证`、`存在差异`、`条件可用` 或 `不可用`。

#### Scenario: 字段能够进入下游契约
- **WHEN** 某个字段被 Dashboard、统一流水、模型目录或请求日志增强设计引用
- **THEN** 来源矩阵中存在与冻结版本匹配的字段级实测证据，且其语义、单位、缺失条件和适用范围均已明确

#### Scenario: 字段名称存在但语义未确认
- **WHEN** 响应中出现名称类似协议、TTFT、费用、退款或 Key 标识的字段，但没有足够实测证据确认其含义
- **THEN** 该字段标记为 `条件可用` 或 `不可用`，下游契约不得把它当作确定值，也不得从其他字段猜测回填

#### Scenario: 同一概念存在多个来源
- **WHEN** 请求数、Token、费用或状态可从两个以上接口或字段取得
- **THEN** 矩阵明确唯一权威来源、校验来源及差异处理，不允许下游自行选择口径

### Requirement: 六项 Dashboard 指标口径完整可执行
项目 SHALL 为请求总数、Token 用量、消费总额、活跃 Key、成功率和平均延迟分别冻结可执行定义。每项定义 MUST 包含数据来源、纳入与排除的日志类型或状态、分子与分母、去重键、单位、时间字段、缺失值、异常值、退款影响和不可支持时的返回策略，并分配可版本化的口径标识。

#### Scenario: 计算六项指标
- **WHEN** 下游聚合实现使用已冻结口径处理同一组脱敏样例
- **THEN** 六项指标均能得到唯一结果，或依据明确规则得到"不可用"，不存在由实现者临时解释的分支

#### Scenario: 指标缺少可信字段
- **WHEN** 某项指标的分子、分母、去重键或单位无法由已验证字段完整支持
- **THEN** 该指标明确标记为暂不支持并返回缺失语义，不以零、百分之百、估算值或前端计算伪装为已支持

#### Scenario: 汇总与趋势使用同一口径
- **WHEN** 后续 Dashboard 同时展示汇总指标和趋势分桶
- **THEN** 两者引用相同口径版本、权威字段及纳入排除规则，趋势合计差异仅能来自已记录的上游时效边界

### Requirement: 消费汇总与统一流水映射可追溯
项目 SHALL 冻结充值、消费和退款的来源映射，明确每种流水的来源接口与记录类型、方向、金额字段、币种或额度单位、状态、发生时间、稳定 ID 构成、可公开引用及去重规则。统一流水 MUST 保持只读，且不得依据金额正负号单独推断业务类型。

#### Scenario: 构造稳定流水记录
- **WHEN** 同一冻结版来源记录被重复读取
- **THEN** 它产生相同且带来源命名空间的稳定流水 ID，并可通过安全引用追溯到来源类型和原始记录

#### Scenario: 无法确认退款来源
- **WHEN** 实测无法找到可与原消费可靠关联的退款类型、标识或金额字段
- **THEN** 退款能力标记为 `条件可用` 或 `不可用`，不得把负值、错误日志或人工备注推断成退款

#### Scenario: 来源状态未知
- **WHEN** 充值、消费或退款记录出现未验证状态
- **THEN** 映射结果使用明确的未知状态或拒绝纳入，并保留诊断证据，不将其默认为成功

### Requirement: 时间范围与分桶契约被冻结
项目 SHALL 冻结带时区 ISO 8601 输入、秒级精度、`[startTime,endTime)` 边界、服务端 UTC 运算、IANA 时区自然日解释、允许粒度、空桶处理和各粒度最大查询跨度。所有上游时间参数转换 MUST 记录其包含性、时间单位和时区语义。

#### Scenario: 相邻区间统计
- **WHEN** 两个查询区间首尾相接
- **THEN** 边界记录只进入其中一个区间，不重复也不因单位转换而遗漏

#### Scenario: 解释用户自然日
- **WHEN** 用户以一个存在夏令时切换的 IANA 时区查询自然日
- **THEN** 自然日先在该时区确定边界，再转换为 UTC，实际跨度允许为 23、24 或 25 小时

#### Scenario: 请求不支持的范围组合
- **WHEN** 查询跨度、粒度或时区不在冻结矩阵允许范围内
- **THEN** 后续服务在访问上游前返回稳定参数错误，不降级为无界查询或擅自更换粒度

### Requirement: 金额和额度精度规则唯一
项目 SHALL 明确每个费用、额度、充值和退款字段的原始单位、币种、换算配置、十进制精度、舍入模式和展示方向。汇总与明细 MUST 使用同一换算规则，计算过程 MUST 使用十进制类型，缺失或未知币种不得按零金额处理。

#### Scenario: 汇总明细金额
- **WHEN** 多条消费明细汇总为指定范围消费额
- **THEN** 汇总按冻结的原始精度累计并在规定阶段舍入，与逐条展示采用同一换算版本

#### Scenario: 金额单位无法确认
- **WHEN** 字段数值存在但无法确认是 quota、最小货币单位还是币种金额
- **THEN** 该字段不得参与正式金额计算，并在来源矩阵中标记限制原因

### Requirement: 查询性能基线可复现
项目 SHALL 在记录硬件、冻结镜像、数据准备、测试用户规模、网络条件和测量方法的前提下，对 24 小时、7 天和 30 天范围记录每个上游接口的调用次数、分页数、记录数、响应字节数、端到端耗时及失败情况。每个范围 MUST 至少包含一次冷启动测量和多次稳定测量，并记录中位数与高分位结果；测试数据不足时 MUST 明确证据限制，不得外推为生产结论。

#### Scenario: 确定聚合保护边界
- **WHEN** LANG-P2-02 设计最大页数、最大记录数、总超时和缓存策略
- **THEN** 每个边界都能追溯到本性能基线或被明确标记为保守安全上限

#### Scenario: 30 天查询成本不可接受
- **WHEN** 30 天实时读取超过冻结的延迟、调用次数或数据量目标
- **THEN** 基线记录瓶颈与失败证据，并触发独立的预聚合存储决策，不在本变更中直接引入数据库、队列或数据仓库

### Requirement: 冻结成果约束后续聚合开发
项目 SHALL 为字段来源、统计口径、流水映射、时间金额规则和性能边界发布一个一致的基线版本。LANG-P2-02 至 LANG-P2-09 的正式契约 MUST 引用该版本；任何改变既有指标结果、流水分类、时间边界、金额结果或字段可用性的调整 MUST 作为显式兼容性变更重新验证。

#### Scenario: 后续实现使用未验证字段
- **WHEN** 下游设计或代码引用来源矩阵中未记录、`条件可用` 或 `不可用` 的字段作为确定值
- **THEN** 契约检查失败，除非先补充实测证据并发布新的基线版本

#### Scenario: 上游升级改变数据语义
- **WHEN** New API 升级导致字段、日志类型、状态、单位、边界或性能结果变化
- **THEN** 受影响的基线项目重新实测并升级口径版本，旧结论不得自动沿用
