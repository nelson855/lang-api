# frontend-application-shell Specification

## Purpose

建立承载第一阶段页面的公开站点、认证页和控制台应用壳，并冻结桌面与移动端导航及路由行为，使后续功能可以逐页接入而不重构整体信息架构。

## Requirements

### Requirement: 三类应用布局
前端 SHALL 提供公开站点布局、认证布局和控制台布局。公开布局包含品牌、主要导航、登录/注册入口和最小页脚；认证布局聚焦账户操作；控制台布局包含品牌区、业务导航、页面标题区和主内容区。所有布局 MUST 使用共享设计系统且不得渲染 New API 品牌或管理入口。

#### Scenario: 公开页面布局
- **WHEN** 用户访问首页、模型广场或开发文档
- **THEN** 页面使用公开站点布局，并在桌面和移动端提供一致的主要目的地

#### Scenario: 认证页面布局
- **WHEN** 用户访问登录或注册路由
- **THEN** 页面使用独立认证布局，保留返回首页入口且不显示虚假的第三方登录或验证方式

#### Scenario: 控制台布局
- **WHEN** 控制台壳在已认证上下文中渲染
- **THEN** 页面显示控制台导航、当前页面标题和内容区域，不展示 New API 管理能力

### Requirement: 响应式导航
桌面宽度 SHALL 显示适合当前布局的常驻导航；窄屏 SHALL 使用可明确打开和关闭的移动导航。移动导航打开后 MUST 管理焦点、阻止背景误操作，并在选中目标、按 Escape 或激活关闭按钮后关闭。

#### Scenario: 桌面导航
- **WHEN** 视口达到桌面断点
- **THEN** 主要目的地常驻可见，当前路由具有视觉和可访问的选中状态

#### Scenario: 移动导航
- **WHEN** 用户在窄屏打开移动导航并选择目标
- **THEN** 导航关闭、页面进入目标路由，焦点落在新页面的合理位置

### Requirement: 第一批路由表面
前端 SHALL 声明 `/`、`/models`、`/docs`、`/login`、`/register` 和 `/dashboard` 路由，并为其他路径提供前端 404。路由切换 MUST 使用客户端导航且直接刷新任一路由仍由一体化应用恢复；每个页面 MUST 设置与当前语言及运行时站点名称一致的文档标题。

#### Scenario: 公开路由导航
- **WHEN** 用户通过站内导航访问首页、模型广场或开发文档
- **THEN** 页面不整页刷新即可切换，主标题和文档标题与目标页面一致

#### Scenario: 直接刷新深层路由
- **WHEN** 用户直接刷新 `/models`、`/docs`、`/login` 或 `/dashboard`
- **THEN** Spring Boot 返回 SPA 入口且前端恢复对应路由或按鉴权守卫重定向

#### Scenario: 未知前端路由
- **WHEN** 用户访问不属于服务端 API 或静态资源的未知页面路径
- **THEN** 前端显示自有 404 页面，而不是浏览器或 Spring Boot 默认错误页

### Requirement: 占位页真实表达阶段状态
模型广场、开发文档、登录、注册和控制台在对应业务尚未交付时 SHALL 使用明确的阶段占位内容，说明功能尚未开放或将在后续阶段接入。占位页 MUST NOT 展示伪造模型、价格、用户、用量、余额、认证结果或可点击但无行为的主要操作。

#### Scenario: 尚未接入模型数据
- **WHEN** 用户在 LANG-P1-08 前访问模型广场
- **THEN** 页面显示功能准备状态，不展示静态伪造模型或价格

#### Scenario: 尚未接入认证
- **WHEN** 用户在 LANG-P1-05 前访问登录或注册页
- **THEN** 页面不提交伪造认证请求，也不宣称账户操作成功
