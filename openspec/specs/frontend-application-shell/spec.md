# frontend-application-shell Specification

## Purpose

建立承载第一阶段页面的公开站点、认证页和控制台应用壳，并冻结桌面与移动端导航及路由行为，使后续功能可以逐页接入而不重构整体信息架构。
## Requirements
### Requirement: 三类应用布局
前端 SHALL 提供共享 Clear Circuit 浅色视觉语言但密度有别的公开站点布局、认证布局和控制台布局。公开布局 SHALL 包含品牌、主要导航、登录/注册入口、主内容和结构化页脚；认证布局 SHALL 使用聚焦账户操作的独立内容面板并保留返回首页和法律入口；控制台布局 SHALL 在桌面使用常驻业务侧栏、顶部上下文栏和可滚动主内容区，在窄屏使用可访问导航抽屉。所有布局 MUST 使用共享设计系统且不得渲染 New API 品牌或管理入口。

#### Scenario: 公开页面布局
- **WHEN** 用户访问首页、模型广场、开发文档、服务地区或法律页面
- **THEN** 页面使用宽松的公开布局、清晰主导航和结构化页脚，并在桌面和移动端提供一致的真实目的地

#### Scenario: 认证页面布局
- **WHEN** 用户访问登录或注册路由
- **THEN** 页面使用聚焦表单的 Clear Circuit 认证面板，表单与输入框保持受控宽度和适中高度，提供返回首页与适用法律入口，且不显示虚假的第三方登录或验证方式

#### Scenario: 控制台布局
- **WHEN** 控制台壳在已认证上下文中渲染
- **THEN** 桌面显示常驻业务侧栏、当前路由标记、用户身份区域、顶部上下文和主内容区，页面数据成为视觉主体且不展示 New API 管理能力

#### Scenario: 控制台窄屏布局
- **WHEN** 控制台进入窄屏或 200% 缩放后的重排宽度
- **THEN** 常驻侧栏切换为模态导航抽屉，背景不可误操作，抽屉支持 Escape 和焦点恢复，主内容保持可读且主要操作可达

### Requirement: 响应式导航
桌面宽度 SHALL 显示适合当前布局的常驻导航；窄屏 SHALL 使用可明确打开和关闭的移动导航。移动导航打开后 MUST 管理焦点、阻止背景误操作，并在选中目标、按 Escape 或激活关闭按钮后关闭。

#### Scenario: 桌面导航
- **WHEN** 视口达到桌面断点
- **THEN** 主要目的地常驻可见，当前路由具有视觉和可访问的选中状态

#### Scenario: 移动导航
- **WHEN** 用户在窄屏打开移动导航并选择目标
- **THEN** 导航关闭、页面进入目标路由，焦点落在新页面的合理位置

### Requirement: 第一批路由表面
前端 SHALL 声明 `/`、`/models`、`/docs`、`/terms`、`/privacy`、`/regions`、`/login`、`/register` 和 `/dashboard` 路由，并为其他路径提供前端 404。路由切换 MUST 使用客户端导航且直接刷新任一路由仍由一体化应用恢复；每个页面 MUST 设置与当前语言及运行时站点名称一致的文档标题。

#### Scenario: 公开路由导航
- **WHEN** 用户通过站内导航访问首页、模型广场、开发文档、法律内容或服务地区
- **THEN** 页面不整页刷新即可切换，主标题和文档标题与目标页面一致

#### Scenario: 直接刷新深层路由
- **WHEN** 用户直接刷新任一声明的公开、认证或控制台路由
- **THEN** Spring Boot 返回 SPA 入口且前端恢复对应路由或按鉴权守卫重定向

#### Scenario: 未知前端路由
- **WHEN** 用户访问不属于服务端 API 或静态资源的未知页面路径
- **THEN** 前端显示带返回首页和支持入口的自有 404 页面，而不是浏览器或 Spring Boot 默认错误页

### Requirement: 占位页真实表达阶段状态
模型广场和开发文档在 LANG-P1-08 交付后 SHALL 分别展示来自 `GET /portal/api/models` 的真实模型目录和基于运行时公开配置生成的真实开发文档；在后端能力尚未就绪、目录为空或模型协议未启用时 SHALL 展示对应真实状态。页面 MUST NOT 展示伪造模型、价格、Base URL、用量、余额、认证结果或可点击但无行为的主要操作；登录、注册和控制台 SHALL 使用 LANG-P1-05 已交付的真实认证状态。

#### Scenario: 尚未接入模型数据
- **WHEN** 部署版本早于 LANG-P1-08，尚未提供真实模型目录接口
- **THEN** 模型广场显示功能准备状态，不展示静态伪造模型或价格

#### Scenario: 尚未接入认证
- **WHEN** 部署版本早于 LANG-P1-05，尚无真实认证接口
- **THEN** 登录或注册页不得提交伪造认证请求，也不得宣称账户操作成功

#### Scenario: 模型目录正常可用
- **WHEN** 用户访问模型广场且模型目录接口成功返回数据
- **THEN** 页面展示真实模型、基础价格和筛选操作，不再显示阶段占位内容

#### Scenario: 模型目录尚无数据
- **WHEN** 用户访问模型广场且接口成功返回空目录
- **THEN** 页面显示当前尚未配置公开模型，不使用静态示例填充页面

#### Scenario: 开发文档的模型协议未启用
- **WHEN** 用户访问开发文档且 public-config 未返回 OPENAI Base URL
- **THEN** 页面显示可阅读的鉴权与接口范围说明以及服务未开放状态，不提供不可用命令的复制操作

#### Scenario: 认证阶段已经交付
- **WHEN** 用户访问登录、注册或控制台入口
- **THEN** 页面使用真实认证选项与会话状态，不宣称未接入认证或展示伪造成功结果

#### Scenario: 从模型广场查看示例
- **WHEN** 用户在一个真实模型条目上选择“查看调用示例”
- **THEN** 应用使用客户端导航进入开发文档，并安全携带该模型 ID 作为示例选择

### Requirement: 可用登录页面
`/login` SHALL 提供用户名和密码表单、客户端基础校验、提交中状态和安全错误反馈。登录成功后 SHALL 导航至合法 `returnTo` 或默认控制台；已登录用户访问登录页 SHALL 被引导到控制台。页面 MUST NOT 提供未实现的 OAuth、MFA、Passkey 或忘记密码流程。

#### Scenario: 提交正确凭据
- **WHEN** 匿名用户填写合法凭据并登录成功
- **THEN** 页面进入安全返回地址或 `/dashboard`，且不会在 URL 或浏览器存储中保留密码

#### Scenario: 提交错误凭据
- **WHEN** 服务端返回 `INVALID_CREDENTIALS`
- **THEN** 页面显示统一凭据错误，不说明用户名是否存在或账户是否被禁用

#### Scenario: 已登录访问登录页
- **WHEN** authenticated 用户打开 `/login`
- **THEN** 页面不重复显示登录表单并导航到控制台

### Requirement: 注册页面服从运行时策略
`/register` SHALL 以认证选项为唯一展示依据：公开注册开启时显示用户名、密码和确认密码表单；关闭时根据 `registrationDisabledReason` 展示管理员关闭、预览模式或法律正文未就绪的准确说明且不显示可提交表单。页面 MUST 始终提供用户协议与隐私政策入口；公开布局的注册入口 MUST 同步隐藏或改为不可注册说明，且页面不得展示未启用的邮箱、验证码或邀请码字段。

#### Scenario: 注册开放
- **WHEN** 认证选项返回 `registrationEnabled=true`
- **THEN** 注册页显示可提交的用户名密码表单和两份法律入口，成功后引导到登录页

#### Scenario: 注册关闭
- **WHEN** 认证选项返回 `registrationEnabled=false`
- **THEN** 注册页显示与关闭原因一致的说明和法律入口，不发送注册请求

#### Scenario: 注册策略在加载中
- **WHEN** 认证选项尚未返回
- **THEN** 页面显示加载状态和法律入口，不短暂展示注册表单

### Requirement: 会话状态与退出交互
控制台 SHALL 显示当前用户的安全展示名和退出操作。会话失效后页面 SHALL 清除用户态内容并引导至登录；退出操作在请求进行中 SHALL 防止重复提交，完成或服务器已清除本地凭证的失败结果都 SHALL 进入匿名界面。

#### Scenario: 用户主动退出
- **WHEN** 已登录用户触发退出
- **THEN** 页面等待一次退出请求完成、清除用户态并导航到公开页或登录页

#### Scenario: 控制台会话过期
- **WHEN** profile 或受保护请求返回 `UNAUTHENTICATED`
- **THEN** 控制台不继续显示旧用户内容，并引导到带安全 returnTo 的登录页

#### Scenario: 重复点击退出
- **WHEN** 首次退出请求仍在进行中
- **THEN** 后续点击不会产生并发退出请求

### Requirement: 受保护的 API Key 页面与导航
控制台 SHALL 增加指向 `/api-keys` 的 API Key 导航和受保护路由。页面 SHALL 提供名称搜索、状态筛选、分页、创建入口，并对加载、空结果、首次无 Key、错误及结果未确认状态给出明确反馈；桌面使用表格或等价密集视图，窄屏使用不横向溢出的可操作布局。

#### Scenario: 已登录访问 API Key 页面
- **WHEN** authenticated 用户从控制台导航进入 `/api-keys`
- **THEN** 页面加载当前用户列表并显示搜索、筛选、分页与创建操作

#### Scenario: 匿名直接访问
- **WHEN** anonymous 用户直接访问或刷新 `/api-keys`
- **THEN** 鉴权守卫跳转登录并保存经过校验的站内返回路径

#### Scenario: 首次空状态
- **WHEN** 当前用户尚未创建任何 Key
- **THEN** 页面解释 Key 的用途并提供真实创建入口，不显示伪造数据

### Requirement: API Key 创建与编辑界面
页面 SHALL 使用同一字段模型提供创建与编辑表单：名称和常用额度/期限字段默认可见，模型限制与 IP 限制置于明确的高级区域。表单 SHALL 展示 quota 单位、无限额度和永不过期语义，阻止非法或矛盾输入，并在提交期间防止重复操作；创建成功后 SHALL 刷新列表并显示一次指向 reveal/复制操作的明确提示。

#### Scenario: 创建有限 Key
- **WHEN** 用户填写合法名称、有限 quota 和未来过期时间并提交
- **THEN** 页面只发送一次创建请求，成功后关闭表单、刷新列表并提示显示和复制新 Key

#### Scenario: 展开高级限制
- **WHEN** 用户打开高级区域
- **THEN** 页面允许配置模型名称数组和 IPv4/IPv6 字面量列表，并在提交前标出非法项

#### Scenario: 编辑保留现有值
- **WHEN** 用户打开已有 Key 的编辑界面并只修改一个字段
- **THEN** 其他已加载公开字段保持原值，页面不要求或展示完整 Key

### Requirement: API Key 风险操作交互
启停、删除和 reveal SHALL 使用与风险相匹配的明确操作文案和确认流程。删除确认必须包含目标 Key 名称；reveal 确认必须说明完整值可用于消费账户额度；明文默认隐藏，显示后支持复制并在关闭或复制成功时清除。任何失败 SHALL 保留安全 requestId，并不得展示上游原始消息或完整 Key。

#### Scenario: 确认停用
- **WHEN** 用户选择停用一个启用中的 Key
- **THEN** 页面说明该 Key 将不能继续调用，确认后才发送一次状态请求

#### Scenario: 确认删除
- **WHEN** 用户选择删除一个 Key
- **THEN** 页面在包含 Key 名称的确认对话框中说明不可恢复，确认后才发送一次删除请求

#### Scenario: 显示并复制
- **WHEN** 用户确认 reveal 后复制完整 Key
- **THEN** 页面写入剪贴板、显示不含敏感值的结果提示并清除当前显示的明文

### Requirement: API Key 页面本地化与可访问性
API Key 页面、表单、状态、确认和错误文案 SHALL 完整提供中文与英文资源。搜索、筛选、表单、对话框和操作菜单 MUST 可通过键盘使用，焦点在打开/关闭对话框时正确管理，状态不只依赖颜色表达；窄屏主要操作保持可触达。

#### Scenario: 切换语言
- **WHEN** 用户在 API Key 页面切换中英文
- **THEN** 标题、字段、状态、单位、验证、确认和通知同步切换且不出现缺失键

#### Scenario: 键盘完成风险操作
- **WHEN** 键盘用户打开 reveal 或删除确认并取消或完成操作
- **THEN** 焦点被限制在对话框内，关闭后返回触发控件，且屏幕阅读器获得明确结果反馈

### Requirement: 基础用量控制台路由与导航
控制台 SHALL 将 `/dashboard` 作为基础用量概览首页，并增加 `/dashboard/request-logs` 受保护路由及“请求日志”导航。两个路由 MUST 复用现有控制台布局、会话守卫、页面标题和移动抽屉行为；不得新增顶层 `/request-logs` 或重复的 `/usage` 页面。

#### Scenario: 已登录访问基础概览
- **WHEN** authenticated 用户进入 `/dashboard`
- **THEN** 页面展示真实余额与基础用量区域，不再显示 Dashboard 阶段占位内容

#### Scenario: 从控制台导航到请求日志
- **WHEN** 用户通过桌面侧栏或移动抽屉选择“请求日志”
- **THEN** 应用使用客户端导航进入 `/dashboard/request-logs`，导航选中状态和页面标题同步更新

#### Scenario: 匿名直接访问请求日志
- **WHEN** anonymous 用户直接访问或刷新 `/dashboard/request-logs`
- **THEN** 会话守卫跳转登录，并保存经过校验的完整站内 returnTo

#### Scenario: 顶层旧式路径
- **WHEN** 用户访问未声明的 `/request-logs` 或 `/usage`
- **THEN** 应用按未知前端路由处理，不渲染控制台数据

### Requirement: 控制台数据局部状态隔离
Dashboard 的余额、摘要和趋势 SHALL 使用独立加载、成功、空数据与错误区域；请求日志页面 SHALL 使用独立分页查询。任一只读接口失败不得清除其他接口已成功的数据，只有 `UNAUTHENTICATED` SHALL 触发统一会话失效流程。所有区域 MUST 使用共享设计系统并在窄屏下保持可读和可操作。

#### Scenario: 单个 Dashboard 区域失败
- **WHEN** 三个 Dashboard 请求中只有一个失败
- **THEN** 页面仅在该区域显示错误和重试，保留其他成功区域

#### Scenario: 会话统一失效
- **WHEN** 任一受保护用量接口返回 `UNAUTHENTICATED`
- **THEN** 应用清除认证范围缓存并进入登录流程，不继续显示余额或日志快照

#### Scenario: 窄屏查看请求日志
- **WHEN** 用户在窄屏访问请求日志并操作筛选与分页
- **THEN** 内容不产生整页横向溢出，主要筛选、状态和分页仍可通过键盘与触摸操作

### Requirement: 钱包与个人设置路由及导航
控制台 SHALL 增加 `/dashboard/wallet` 和 `/dashboard/settings` 两个受保护路由，并在桌面侧栏与移动抽屉提供“钱包”和“个人设置”导航。两个页面 MUST 复用现有控制台布局、会话守卫、页面标题、移动导航和用户作用域缓存清理行为；不得新增顶层 `/wallet`、`/topup`、`/settings` 或暴露 New API 原始页面。

#### Scenario: 从控制台进入钱包
- **WHEN** authenticated 用户通过桌面或移动导航选择钱包
- **THEN** 应用使用客户端导航进入 `/dashboard/wallet`，同步更新导航选中状态和页面标题

#### Scenario: 从控制台进入个人设置
- **WHEN** authenticated 用户通过桌面或移动导航选择个人设置
- **THEN** 应用使用客户端导航进入 `/dashboard/settings`，并以当前认证 profile 初始化页面

#### Scenario: 匿名直接访问
- **WHEN** anonymous 用户直接访问或刷新钱包或个人设置路由
- **THEN** 会话守卫跳转登录，并保存经过校验的完整站内 returnTo

#### Scenario: 顶层旧式路径
- **WHEN** 用户访问未声明的 `/wallet`、`/topup` 或 `/settings`
- **THEN** 应用按未知前端路由处理，不渲染钱包、资料或上游页面

### Requirement: 钱包页面局部状态与响应式行为
钱包页面 SHALL 独立查询余额、充值能力和充值记录；任一只读请求失败不得清除其他成功数据，只有 `UNAUTHENTICATED` SHALL 触发统一会话失效。充值记录分页、各区域重试和关闭说明 MUST 可通过键盘与触摸操作，并在窄屏下不产生整页横向溢出。

#### Scenario: 充值记录失败但余额成功
- **WHEN** 余额查询成功而充值记录查询失败
- **THEN** 页面保留余额和充值关闭说明，只在记录区域显示错误与重试

#### Scenario: 会话失效
- **WHEN** 任一钱包或设置接口返回 `UNAUTHENTICATED`
- **THEN** 应用清除全部用户作用域缓存并进入登录流程，不继续显示旧余额、记录或 profile

#### Scenario: 窄屏查看钱包
- **WHEN** 用户在窄屏查看余额、关闭说明和充值记录分页
- **THEN** 主要内容不产生整页横向溢出，状态、订单号与分页保持可读可操作

### Requirement: 完整公开站点导航与内容闭环
公开布局 SHALL 在桌面和移动端提供首页、模型、文档、服务地区及适用的登录/注册目的地；页脚 SHALL 提供用户协议、隐私政策、服务地区和运行时支持入口。首页 MUST 使用真实站点名、当前开放协议与可到达的主要操作解释产品价值，不得包含虚构客户、指标、价格、能力或无行为按钮。

#### Scenario: 公开站点主要目的地
- **WHEN** 匿名用户从首页使用桌面导航、移动导航或页脚
- **THEN** 所有展示的内部链接都到达声明路由，支持入口使用 public-config 的受校验值

#### Scenario: 能力尚未开放
- **WHEN** public-config 没有公开模型协议或部署为 `PREVIEW`
- **THEN** 首页准确显示准备状态，不把注册或调用入口描述为已正式可用

#### Scenario: 移动导航访问新增页面
- **WHEN** 窄屏用户打开导航并选择服务地区或其他公开目的地
- **THEN** 导航按既有焦点规则关闭并进入目标页面，不产生背景误操作

### Requirement: 服务地区页面来源真实
`/regions` SHALL 只根据 public-config 的 `supportedRegions` 展示服务地区，并使用本地受控地区名称映射；空列表时显示尚未公布状态。页面 MUST 说明地区列表属于当前服务可用范围，不推导数据驻留、付款方式、税务、合规认证或未声明的服务承诺。

#### Scenario: 展示已配置地区
- **WHEN** public-config 返回一个或多个受支持地区代码
- **THEN** 页面以当前界面语言展示对应名称，且保留代码用于无歧义表达

#### Scenario: 地区尚未公布
- **WHEN** public-config 返回空地区数组
- **THEN** 页面显示未发布状态和支持入口，不使用推测地区填充

### Requirement: 品牌资产与公开 Meta 一致
前端 SHALL 复用自有 `L/` 几何标识作为 MVP Logo，并提供同源 favicon、文本替代和可集中替换的资产入口。公开路由 SHALL 基于运行时站点名和当前语言设置 title、description、canonical 与 robots；`PREVIEW`、404、错误或未发布法律页面 MUST 为 `noindex`，只有 `PUBLIC` 中有效的公开页面可索引。源码、构建产物、公开响应和用户可见错误不得残留 QinghuaAPI、New API 私网地址或上游默认品牌。

#### Scenario: 正式公开页面 Meta
- **WHEN** `PUBLIC` 模式下用户访问有效公开页面
- **THEN** 页面生成以 `siteUrl` 为基准的同源 canonical、对应语言标题和描述，并允许索引

#### Scenario: 预览或错误页面 Meta
- **WHEN** 部署为 `PREVIEW` 或当前页面为 404、错误、未发布法律状态
- **THEN** 页面声明 `noindex`，且不生成指向错误地址的 canonical

#### Scenario: 品牌残留检查
- **WHEN** 自动化检查前端源码、构建产物、公开接口夹具和用户可见文案
- **THEN** 不出现被禁止的上游品牌、私网域名或默认站点资产

### Requirement: 首页快速接入叙事
首页 SHALL 采用非对称的“中文价值主张 + 真实快速接入终端”首屏。首屏 SHALL 使用运行时站点名、经过校验的 Base URL、当前可用协议和可到达的注册/控制台/文档操作；终端代码和请求状态 MUST 来自真实配置或明确标识的静态语法模板，不得伪造已经发生的用户请求、性能、客户或业务指标。首屏之后 SHALL 依次提供真实协议能力、真实模型目录摘要、三步接入说明和最终行动入口，并保持与 QinghuaAPI 不同的信息结构。

#### Scenario: 公开协议与模型可用
- **WHEN** `PUBLIC` 模式存在受支持协议且模型接口返回一个或多个公开模型
- **THEN** 首页快速接入终端使用真实 Base URL，模型摘要展示真实模型内容，主操作到达注册或已登录控制台，次操作到达开发文档或模型广场

#### Scenario: 协议尚未开放
- **WHEN** public-config 没有公开模型协议
- **THEN** 首页将终端和主要行动切换为准确的未开放状态，不展示可复制的不可用 Base URL，也不伪装请求成功

#### Scenario: 模型目录为空或失败
- **WHEN** 模型目录成功返回空集合或摘要加载失败
- **THEN** 首页在模型摘要区域分别显示真实空状态或局部错误与重试，不使用示例模型填充，也不影响首屏其他已成功内容

#### Scenario: 预览发布模式
- **WHEN** public-config 返回 `PREVIEW`
- **THEN** 首页保留视觉结构但明确展示预览状态，不把注册、模型调用或服务承诺描述为已正式开放

### Requirement: 全站页面视觉迁移
首页、模型广场、开发文档、服务地区、登录、注册、Dashboard、API 密钥、请求日志、钱包、个人设置、用户协议、隐私政策、403、404、启动失败和通用错误页面 SHALL 使用同一 Clear Circuit 令牌与共享组件，不得在同一发布版本中保留旧的深色页面主题或浏览器默认控件。迁移 MUST 保持既有路由、查询、提交、风险确认、会话失效、真实数据、SEO 和缓存清理行为。

#### Scenario: 跨页面连续浏览
- **WHEN** 用户从公开首页依次进入模型、文档、认证页面并登录进入任一控制台页面
- **THEN** 每个页面保持一致的品牌、控件、状态和动效语义，同时通过公开区与控制台密度差异表达不同使用场景，不出现旧主题或无样式页面闪现

#### Scenario: 高风险流程迁移
- **WHEN** 用户在新视觉下显示、复制、停用或删除 API 密钥，或修改密码
- **THEN** 页面只改变布局与视觉呈现，继续执行既有确认强度、敏感值清理、重复提交防护、错误恢复和焦点行为

#### Scenario: 启动与路由错误
- **WHEN** 运行时配置加载失败、路由渲染失败、用户无权限或路径不存在
- **THEN** 对应状态在适用的 Clear Circuit 应用壳内显示安全说明和恢复入口，不退回无样式文档流或浏览器默认页面

### Requirement: 控制台信息层级与滚动所有权
控制台 SHALL 使用固定宽度侧栏、顶部上下文栏、页面标题区和独立内容区域建立稳定信息层级。Dashboard 的余额、摘要和趋势 SHALL 以独立面板呈现；表格页 SHALL 将工具栏、表格和分页组合为一个数据区域，并明确该区域的横向或纵向滚动所有权。任何表格适配 MUST NOT 在共享控制台壳、页面祖先或相邻长表单上施加仅为表格服务的固定视口高度或 `overflow: hidden`。

#### Scenario: Dashboard 局部状态
- **WHEN** 余额、摘要或趋势中的一个区域加载、失败或刷新
- **THEN** 只有对应面板显示稳定尺寸的状态反馈，其他面板和页面标题不位移且继续可用

#### Scenario: 桌面数据表
- **WHEN** 用户在桌面浏览 API 密钥、请求日志或充值记录
- **THEN** 工具栏、表头、行和分页共享一致的密度与边界，表格在自己的容器内处理溢出，不改变整个页面的滚动所有权

#### Scenario: 表格与长表单切换
- **WHEN** 用户从数据列表打开 API 密钥编辑表单或在短视口中使用个人设置长表单
- **THEN** 表单保持自然高度或既有内容滚动方式，所有字段和操作可达，不继承表格专用高度或产生竞争的嵌套纵向滚动条

#### Scenario: 控制台导航位置感
- **WHEN** 用户切换 Dashboard、API 密钥、请求日志、钱包和个人设置
- **THEN** 侧栏当前项、顶部上下文、页面标题和文档标题同步更新，焦点移动到新页面合理位置且侧栏几何保持稳定
