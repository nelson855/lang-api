## Context

动机见 `proposal.md`。本需求跨 New API 日志适配、Portal DTO、前端校验及页面，因证据门槛与旧响应兼容需要明确设计。

当前 `RequestLogQueryService` 固定返回 `protocol=null`、`firstTokenLatencyMs=null`；`NewApiLogEntryRaw` 没有这两项映射。`frontend/src/api/requestLogs.ts` 要求两个字段必须存在，因此旧响应省略字段会整页校验失败。页面已有 USD 费用，但尚未显示协议、TTFT、流式状态或 quota 说明。

证据来源为 `docs/new-api/aggregation-baseline.json`、聚合兼容性矩阵及统计口径文档。当前基线 `p2-2026-09-22-a`：协议与 TTFT 不可用，type=5 的真实样本以及 quotaPerUsd 的独立证据仍不足。字段名和基线 JSON 的候选单位不等于已经验证的语义。

## Goals / Non-Goals

**Goals:** 用单一现有分页接口完成可空增强展示；把“字段未采集”“真实零”“异常增强值”“基础数据损坏”分开；保留用户隔离、已有查询语义和金额口径。

**Non-Goals:** 不扩展网关请求采集，不修补历史记录，不增加日志表或任意 `other` JSON 解析框架，不新增协议/TTFT 筛选，不改变 Dashboard 或钱包正式金额计算，不以本次规划消除 P2-01 外部缺口。

## Decisions

### 1. 实测证据是非空映射的前提

默认实现继续返回两个 null，先完成缺失/兼容/展示链路。实施时复核当前用户 `/api/log/self` 的脱敏样本并建立字段证据表，至少记录版本、路径、类型、原值单位、转换方式、覆盖协议、流式/非流式、成功/失败以及测量起止点。无证据明确写不可用，不用模拟样本修改基线结论。

如果实际运行环境提供新证据，启用之前必须更新本 change 的 delta spec、设计和任务，冻结具体映射及单位并补充真实样本。该步骤属于显式契约调整；本版不预设 `first_token_time` 是毫秒，也不预设协议藏在 `other` 中。无法取得外部证据时，页面与兼容任务仍可推进，真实非空字段验收保持阻塞。

考虑过按模型/端点推断协议以及在网关新增计时：前者不可信，后者扩大到请求执行链路与数据写入，本次不采用。

### 2. 对外保持 DTO，前端仅放宽两个增强字段

保留 `RequestLogDto` 字段名称和现有分页包装，不新增 availability 元数据或第二个日志接口。生产后端继续明确序列化两个 null；当前不需要改 raw record 或所有聚合消费者的构造函数。

前端对 protocol 和 firstTokenLatencyMs 单独归一化：缺失/null → null；合法受控协议 → 原值；合法非负安全整数 TTFT → 毫秒值；其余 → null。基础字段和未声明字段仍按现有严格 schema 校验，避免整体 `.passthrough()`。

为使已有可空协议能被安全展示，前端展示词表限定为 `OPENAI`、`ANTHROPIC`、`GEMINI`，只作为 Portal 值的展示支持；当前后端仍全部返回 null，词表不构成上游映射依据或公共协议开放承诺。未知字符串不直接展示。未来新协议需要显式扩展契约与测试。

合法 TTFT 为 0 时用空值判断保留 `0 ms`。对负数、小数、字符串、非有限值及大于 `Number.MAX_SAFE_INTEGER` 的数值降级为 null；不将总耗时作为上下界依据，因为其单位分辨率和测量边界尚不能支持这种推断。若后续映射需要秒转毫秒或舍入，须先通过证据冻结规则，并在后端进行受检转换，不由前端猜单位。

考虑过任何增强值非法都整页失败：会让基础数据正常的历史页不可读，故只对可选字段降级，基础非法仍安全失败。

### 3. 费用保持一个权威换算路径

继续使用 `QuotaMoneyConverter` 与现有 `portal.catalog.quota-per-usd`。当前实现十进制除法保留 10 位后按最多 6 位展示舍入，输出 plain string；本需求不改舍入策略。请求日志、Dashboard 与消费汇总复用该口径。

前端直接呈现 amount + USD，quota 保持字符串，可在费用单元格次级文本中展示 `额度：<quota> quota`，不调用 Number/parseFloat 或 Intl 数值格式化重算。短说明说明“费用按日志额度和配置换算；不代表额外计费项目或正式账单”。说明可折叠但须有可键盘访问的按钮和区域，默认在页面保留简短说明，不仅靠 hover tooltip。

验证比较相同 `[startTime,endTime)` 内同一组成功记录的 quota；汇总先累加 quota 后舍入，逐行费用相加可能有舍入差异，必须说明，不能修改正式汇总来“对齐”页面。未经独立证据核对，不宣称配置 USD 与实际结算金额等值。

### 4. 增强原表格，不创建新的详情流程

沿用 RequestLogsPage 与 DESIGN.md 的 Clear Circuit 风格、共享 Table、控件及反馈组件。建议列顺序：时间、Key、模型、协议、流式状态、输入/输出 Token、总耗时、TTFT、结果、费用、请求 ID。协议和 TTFT 不可用时逐项显示本地化暂无数据；流式状态只读取 stream。

TTFT 列及页面说明首次解释为“首 Token 延迟：从请求开始到收到第一个输出 Token 的耗时”，并指出数据不可用不等于零，总耗时另列。数据区维持语义 table、局部横向滚动和可见滚动提示，375px 下筛选/分页保留自然文档滚动，完整费用、quota、模型与 requestId 可访问。中英文覆盖标题、说明、错误和可访问名称；技术值保留原文。

保留现有提交式查询，不引入实时远程搜索；清除输入保留已有清除/提交规则。沿用 URL 已提交筛选、页码恢复与 Dashboard 下钻。加载保留兼容几何，错误保留重试，迟到响应不可覆盖新查询；401 清除认证缓存后进入原登录流程。用模型广场/钱包既有状态和表格组件保证一致性，无需全站改造 DESIGN.md。

考虑过用抽屉承载增强字段：只增加三项，现有表格可容纳，抽屉增加焦点与返回状态复杂度，因此不采用。

### 5. 不增加查询能力与运行配置

后端仍只允许既有分页、时间、Key、模型和 SUCCESS/ERROR 条件，不新增 protocol/TTFT 参数，不在一页内过滤伪造 total。上游用户会话只访问 self 日志，禁止管理员接口、任意用户参数与敏感原文透传。

不新增功能开关或运行配置，保持 application.properties 与 application-dev.properties、application-test.properties、application-prod.properties 现有分离及值；后续若增加映射开关需要重新设计，不能用配置任意 JSONPath 代替可信适配逻辑。

## Risks / Trade-offs

- [真实协议/TTFT 不可用] → 交付诚实的 null 状态与兼容链路，外部验收任务保持未完成，不把页面完成当作数据验收完成。
- [type=5 和换算比例独立证据不足] → 沿用现有接口契约，不更改状态或金额，单列真实错误/扣费核对缺口。
- [忽略异常增强值可能掩盖上游漂移] → 用脱敏契约测试与验证记录定位字段问题，不将原始扩展值写入日志或页面。
- [列数增加使窄屏阅读变慢] → 表格局部滚动、字段说明与完整值可访问；浏览器检查滚动区域、键盘及英文长文案。

## Migration Plan

实施顺序：证据复核与冻结当前 null 结论 → 建立响应兼容失败测试 → 校验/展示实现 → 自动化与一体化验证 → 实际字段/费用抽样核对 → 更新文档和任务状态。

没有数据迁移。前后端可空字段名称保持兼容，前端先兼容缺失字段，回退制品不会改写日志。实施阶段执行 Maven verify（使用指定 settings.xml）、前端 test/lint/build、相关 Playwright 和一体化接口验证。发布与实际部署需用户另行授权，本次规划不执行。

自动化使用合成的非空协议/TTFT 数据仅验证展示与归一规则，必须标记为模拟；真实环境继续按当前基线返回 null。现场抽样结果记录环境、版本、时间范围、样本数、quota 与脱敏证据，不记录 Key、正文或用户身份。没有真实证据时保留未完成任务及“受阻”阶段状态。
