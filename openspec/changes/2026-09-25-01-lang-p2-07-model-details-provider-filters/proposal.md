## Why

现有公共模型目录只能支持模型列表与前端临时派生厂商筛选，缺少可独立访问、可与目录快照核对且不会编造能力信息的模型详情和供应商选项契约。P2-01 已冻结 `/api/pricing` 的模型、厂商和基础价格证据，但上下文窗口、能力标签、发布日期及增强价格仍无可靠来源，因此 P2-07 需要先建立“有证据才返回、无证据明确为空”的稳定边界。

## What Changes

- 新增无需认证的 `GET /portal/api/models/{modelId}`，通过安全、规范化的 URL-safe Base64 模型引用查询详情，并返回模型 ID、显示名、供应商、可用性、基础价格、可空限制、模态、能力、发布信息、标签、排序和增强价格。
- 新增无需认证的 `GET /portal/api/model-providers`，从同一公共目录快照派生去重、稳定排序的供应商筛选项和模型数量，不暴露上游厂商 ID、图标、渠道或内部路由。
- 模型详情、供应商选项和现有模型列表复用同一短期缓存快照及 `pricingVersion`；新接口不建立独立且可能漂移的缓存或静态模型主数据。
- 当前 `p2-2026-09-22-a` 只填充已有证据支持的基本字段。上下文窗口、最大输出、输入/输出模态、工具、推理、结构化输出、附件、发布日期、描述、标签、排序和增强价格在证据不足时返回 `null`，不得依据模型名、品牌常识或上游未知字段推断。
- 详情中的基础价格沿用现有模型目录换算契约；缓存、图片、音频、视频和搜索等增强价格只有在后续适配器获得可验证、单位明确的来源时才能返回。
- 增加模型引用编码、非法及不存在模型、特殊字符、字段白名单、快照一致性、供应商去重、缓存并发与上游失败测试，并保留真实调用扣费交叉核对为外部证据任务。
- 保持现有 `GET /portal/api/models` 响应结构和第一阶段前端兼容，不修改 New API，也不实现模型管理后台或自建完整模型主数据。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `model-catalog`: 扩展公共模型目录，增加模型详情、供应商筛选项、可信元数据/增强价格空值语义、安全模型引用以及三类接口的快照一致性要求。

## Impact

- 主要影响 `portal-api` 的 catalog Controller、内部目录快照、详情/供应商 DTO、模型引用编解码、映射白名单和对应测试。
- 继续只读 New API `/api/pricing`，复用现有 Caffeine 单快照缓存、超时、错误映射和 `.properties` 配置；不新增数据库、共享缓存、外部依赖或环境配置项。
- 后续 P2-08 可直接消费详情与供应商接口；P2-09 若引入协议或调用参数说明，应通过独立证据和 delta spec 扩展，不能从 `supported_endpoint_types` 反推模型能力。
- P2-01 仍缺 quotaPerUsd 独立证据、增强价格来源及真实调用扣费样本，因此 P2-07 实施后阶段状态仍应保持“受阻”，并分别记录已交付接口与外部证据缺口。
