## Purpose

为所有公开页面和用户控制台建立独立、可复用且可访问的视觉与交互基础，使后续业务功能共享一致的设计语言，而不是复制参考站或沿用 New API 默认界面。

## ADDED Requirements

### Requirement: 独立视觉语言
前端 SHALL 使用本项目自有的颜色、字体、间距、圆角、阴影、层级、状态色和动效变量构成一致的视觉语言。实现 MUST NOT 复制 QinghuaAPI 的页面比例、导航细节、卡片排列或文案，也不得加载、引用或改色复用 New API 默认前端资源和主题。

#### Scenario: 公开页面视觉一致
- **WHEN** 用户依次访问首页、模型广场、开发文档、登录和注册页
- **THEN** 页面使用相同的品牌标识、排版层级、控件样式和状态语义，并可明确识别为 Lang API 自有界面

#### Scenario: 控制台与公开站点同源但有区分
- **WHEN** 用户比较公开站点与控制台布局
- **THEN** 两者共享设计变量和品牌语言，同时通过导航与内容密度明确区分公开浏览和业务操作场景

### Requirement: 基础交互组件
前端 SHALL 提供可复用的按钮、输入框、表单字段、对话框、表格、分页和通知组件。组件 MUST 支持禁用、加载、校验失败等适用状态，并保持统一的尺寸、焦点和错误表达；对话框和通知等复合组件 MUST 具备正确的焦点管理与可访问语义。

#### Scenario: 键盘操作对话框
- **WHEN** 用户只使用键盘打开、浏览和关闭对话框
- **THEN** 焦点进入并限制在对话框内，Escape 可关闭，关闭后焦点回到触发控件

#### Scenario: 表单校验失败
- **WHEN** 一个表单字段校验失败
- **THEN** 错误文案与字段建立可访问关联，字段呈现错误状态，用户无需仅依赖颜色理解失败原因

#### Scenario: 分页边界
- **WHEN** 列表位于第一页、最后一页或总数为零
- **THEN** 不可用的翻页操作被禁且具备明确标签，不产生无效页码请求

### Requirement: 通用页面状态
前端 SHALL 提供加载、空数据、可重试错误、无权限和 404 状态组件。状态组件 MUST 用明确中文或当前语言解释发生了什么及可执行的下一步，不得依赖浏览器默认错误页面、空白区域或无限加载动画。

#### Scenario: 可重试请求失败
- **WHEN** 页面数据请求失败且允许重新请求
- **THEN** 页面显示安全错误说明、requestId（存在时）和明确重试操作

#### Scenario: 空数据
- **WHEN** 请求成功但集合为空
- **THEN** 页面显示非错误的空状态及与当前真实能力一致的下一步，不伪造示例数据

#### Scenario: 无权限和未找到
- **WHEN** 页面分别进入无权限或未知路由状态
- **THEN** 显示语义不同的 403/404 状态，并提供返回安全页面的导航

### Requirement: 响应式与可访问性基线
页面和基础组件 SHALL 在 320 CSS 像素宽度至常见桌面宽度内保持可操作，不产生页面级横向滚动；数据表可在自身容器内横向滚动。所有交互 MUST 可通过键盘完成，具有可见焦点、可读标签和满足 WCAG AA 的正文及控件对比度；用户选择减少动效时 MUST 关闭非必要动画。

#### Scenario: 窄屏操作
- **WHEN** 用户在 320 CSS 像素宽度的触控设备访问任一基础页面
- **THEN** 主内容、导航、表单和主要操作仍可读可用，且页面不出现整体横向滚动

#### Scenario: 减少动效偏好
- **WHEN** 浏览器声明 `prefers-reduced-motion: reduce`
- **THEN** 页面关闭装饰性过渡与位移动画，同时保留必要的状态变化反馈

#### Scenario: 键盘焦点可见
- **WHEN** 用户通过 Tab 在页面交互元素间移动
- **THEN** 当前焦点始终清晰可见，顺序与视觉阅读顺序一致
