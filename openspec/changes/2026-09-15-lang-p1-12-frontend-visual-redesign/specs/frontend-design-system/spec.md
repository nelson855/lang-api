## MODIFIED Requirements

### Requirement: 独立视觉语言
前端 SHALL 使用 Lang API 自有的 Clear Circuit（明线）浅色视觉语言，以冷调灰白页面背景、白色产品表面、深石墨文字和钴蓝品牌信号构成统一的颜色层级，并通过共享变量统一字体、间距、圆角、阴影、层级、状态色、焦点和动效。钴蓝 MUST 仅用于主操作、当前导航、焦点和关键链接，不得扩散为大面积装饰；成功、警告、危险等语义状态 MUST 使用独立语义色并辅以文字或图标。实现 MUST NOT 复制 QinghuaAPI 的页面比例、导航细节、卡片排列或文案，也不得加载、引用或改色复用 New API 默认前端资源和主题。

#### Scenario: 公开页面视觉一致
- **WHEN** 用户依次访问首页、模型广场、开发文档、服务地区、登录、注册和法律页面
- **THEN** 页面使用相同的 Clear Circuit 品牌标识、排版层级、控件样式和状态语义，并可明确识别为 Lang API 自有界面

#### Scenario: 控制台与公开站点同源但有区分
- **WHEN** 用户比较公开站点与控制台布局
- **THEN** 两者共享设计变量和品牌语言，公开区以宽松留白和快速接入面板建立轻量技术氛围，控制台以灰白画布、白色工作面和更紧凑的信息密度承载长期操作

#### Scenario: 品牌信号保持克制
- **WHEN** 同一页面同时出现主操作、普通卡片、状态信息和危险操作
- **THEN** 钴蓝只强调主操作、当前位置或焦点，普通内容保持中性层级，成功与危险操作使用各自语义色而非品牌色

### Requirement: 基础交互组件
前端 SHALL 提供并复用按钮、图标按钮、输入框、密码字段、搜索字段、表单字段、Select/Listbox、对话框、表格、分页、通知和代码块等共享组件。标准表单控件 SHALL 使用适中密度，搜索、筛选和表格工具栏 SHALL 使用紧凑密度，桌面认证表单的输入区域 MUST NOT 无限铺满容器。组件 MUST 支持适用的默认、悬停、键盘焦点、按下、选中、禁用、只读、加载、校验失败和错误状态，保持统一尺寸与状态语义；加载状态不得改变控件外部尺寸。对话框和通知等复合组件 MUST 具备正确的焦点管理与可访问语义；需要统一弹层几何的单选下拉 MUST 使用维护中的可访问 Select/Listbox，共享触发器与弹层的宽度、边框、圆角和密度。

#### Scenario: 键盘操作对话框
- **WHEN** 用户只使用键盘打开、浏览和关闭普通对话框或风险确认对话框
- **THEN** 焦点进入并限制在对话框内，Escape 按当前操作规则关闭，关闭后焦点回到触发控件或合理后继位置

#### Scenario: 表单校验失败
- **WHEN** 一个表单字段校验失败
- **THEN** 错误文案与字段建立可访问关联，字段呈现文字、图标或结构化错误状态，用户无需仅依赖颜色理解失败原因

#### Scenario: 密码字段显示与隐藏
- **WHEN** 用户在登录、注册或个人设置中操作密码字段
- **THEN** 密码默认被遮蔽，并提供可通过键盘操作且具有动态可访问名称的显示/隐藏按钮，同时保持输入值、焦点和光标位置

#### Scenario: 打开下拉选择器
- **WHEN** 用户打开模型、状态或时间范围等单选控件
- **THEN** 弹层延续 Clear Circuit 视觉，宽度与触发器外宽相差不超过 1 CSS 像素，支持方向键、Enter、Escape、选中与禁用状态，并在视口边缘正确避让和滚动

#### Scenario: 分页边界
- **WHEN** 列表位于第一页、最后一页或总数为零
- **THEN** 不可用的翻页操作被禁且具备明确标签，不产生无效页码请求，也不因禁用状态导致布局跳动

### Requirement: 通用页面状态
前端 SHALL 提供加载、刷新中、空数据、无搜索结果、可重试错误、结果未知、无权限和 404 状态组件。状态组件 MUST 使用当前语言解释发生了什么及可执行的下一步，不得依赖浏览器默认错误页面、空白区域或无限加载动画；初始加载、局部刷新和提交中 MUST 具有可区分的反馈，并在状态切换时保留兼容几何。

#### Scenario: 可重试请求失败
- **WHEN** 页面或独立数据区域请求失败且允许重新请求
- **THEN** 失败区域保留既有页面结构，显示安全错误说明、requestId（存在时）和明确重试操作，不清除其他已成功内容

#### Scenario: 空数据
- **WHEN** 请求成功但集合为空
- **THEN** 页面显示非错误的首次空数据状态及与当前真实能力一致的下一步，不伪造示例数据

#### Scenario: 无搜索结果
- **WHEN** 数据集存在内容但当前搜索或筛选没有匹配结果
- **THEN** 页面显示与首次空数据不同的无结果状态，并提供清除搜索或筛选操作

#### Scenario: 后台刷新
- **WHEN** 已有内容正在后台刷新
- **THEN** 页面保留可用旧内容并显示低干扰刷新状态，不把整个区域替换为空白或造成主要控件位移

#### Scenario: 无权限和未找到
- **WHEN** 页面分别进入无权限或未知路由状态
- **THEN** 显示语义不同的 403/404 状态，保持适用的应用壳，并提供返回安全页面的导航

### Requirement: 响应式与可访问性基线
页面和基础组件 SHALL 在 320 CSS 像素宽度至常见桌面宽度内保持可操作，不产生页面级横向滚动；数据表 SHALL 根据比较需求采用自身横向滚动或等价的窄屏记录布局。所有交互 MUST 可通过键盘完成，具有可见焦点、可读标签和满足 WCAG 2.2 AA 的正文及控件对比度；200% 缩放时除真实二维表格外 MUST 保持单方向可读与可操作。用户选择减少动效时 MUST 关闭位移、缩放和装饰性动效，只保留必要且低干扰的状态反馈。

#### Scenario: 窄屏操作
- **WHEN** 用户在 320 CSS 像素宽度的触控设备访问任一现有页面
- **THEN** 主内容、导航、表单和主要操作仍可读可用，表格溢出具有明确提示或转换为等价记录布局，且页面不出现整体横向滚动

#### Scenario: 200% 缩放
- **WHEN** 用户在代表性桌面视口将页面放大到 200%
- **THEN** 导航、表单、对话框、通知和主要操作重新排布且不被固定区域遮挡，重要文本和值无需二维滚动即可读取

#### Scenario: 减少动效偏好
- **WHEN** 浏览器声明 `prefers-reduced-motion: reduce`
- **THEN** 页面取消终端倾斜、入口位移、缩放和错峰动画，并将必要状态切换限制为不超过 100 毫秒的透明度变化或即时变化

#### Scenario: 键盘焦点可见
- **WHEN** 用户通过 Tab 在页面交互元素间移动
- **THEN** 当前焦点始终清晰可见，不被粘性导航、抽屉、对话框或虚拟键盘遮挡，顺序与视觉阅读顺序一致

#### Scenario: 全局滚动条
- **WHEN** 页面、表格、代码块、菜单或对话框出现产品自有滚动区域
- **THEN** 该区域无需额外工具类即可继承可见、可操作且与浅色主题一致的滚动条，并在强制颜色模式下保留平台可用性和稳定滚动条占位
