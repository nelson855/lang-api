## Why

当前前端已具备完整业务闭环和可访问基础，但页面仍以功能骨架和默认文档流为主，品牌辨识度、信息层级与跨页面视觉一致性不足。现有公开页面尤其首页过于简陋，难以体现 Lang API 作为独立大模型 API 平台的专业度，因此需要在不改变已验证业务契约的前提下完成一次全站视觉与布局重构。

## What Changes

- 建立名为 **Clear Circuit（明线）** 的全站浅色视觉语言：以冷调灰白画布、白色工作面和深石墨文字为基础，以钴蓝作为品牌与交互信号，用细“路由轨迹”表达 API 连接感，并统一字体、间距、边框、圆角、阴影、状态色、焦点和动效变量。
- 重构公开首页为非对称的“价值主张 + 快速接入终端”首屏，随后展示真实协议能力、真实模型目录摘要、三步接入流程和明确行动入口；不复制 QinghuaAPI 的页面比例、四卡片结构、导航细节或文案。
- 重构公开布局、认证布局与控制台布局：公开区保持克制的技术氛围；控制台使用冷调灰白画布、白色工作面和更紧凑的信息密度，形成适合长期使用的固定侧栏、顶部上下文栏和内容工作区。
- 将首页、模型广场、开发文档、服务地区、登录、注册、Dashboard、API 密钥、请求日志、钱包、个人设置、法律内容及通用状态页面统一迁移到新视觉系统。
- 系统化改造按钮、输入框、表单字段、选择控件、对话框、表格、分页、通知、代码块、状态徽标和加载/空数据/错误状态，确保跨页面使用相同视觉与交互语义；搜索和筛选使用紧凑控件，登录/注册表单使用受控宽度和适中行高，不再出现过高或无意义铺满的输入框。
- 继续保持中文与英文资源完整；中文界面以中文承担核心标题和操作表达，英文仅保留在品牌、协议、模型、代码和必要技术标签中。
- 保持现有路由、Portal API 契约、认证与会话规则、风险操作确认、真实数据约束、运行时配置、SEO 门禁和用户作用域缓存行为不变。
- 完善桌面、移动端、键盘、200% 缩放、减少动效、高对比度和稳定滚动区域的视觉与交互验证。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `frontend-design-system`：将现有通用视觉基线升级为 Clear Circuit 全站浅色视觉系统，并补充表面层级、品牌色约束、控件密度、滚动条、布局稳定性和共享组件状态要求。
- `frontend-application-shell`：重新定义公开首页、认证布局和控制台布局的视觉结构与响应式表现，同时保持既有路由、数据和安全行为。
- `frontend-localization`：增加中文界面的语言层级约束，限制非必要中英文混排，并保持 `zh-CN` 与 `en-US` 资源完整和运行时启用规则。

## Impact

- 主要影响 `frontend/src/design/`、`frontend/src/components/`、`frontend/src/layouts/`、`frontend/src/pages/`、品牌资产、国际化资源及对应测试与 E2E 场景。
- 需要建立项目根级 `DESIGN.md` 作为持久视觉决策来源，并将其令牌映射到现有 `tokens.css` 与共享组件；同时新增 `UX-CONTRACT.md`，固化当前多页面应用已有的导航、状态、反馈、风险操作和恢复行为。
- 不新增或修改后端接口、数据库、Portal API 路径、模型网关协议、权限规则与部署拓扑。
- 不引入新的运行时 UI 框架；继续复用 React、现有 Radix Dialog、本地字体和共享组件。为保证应用自有的下拉弹层几何与可访问性，计划只新增与现有 Radix 体系一致的 Select/Listbox 包，不手工实现 ARIA 复合控件。
