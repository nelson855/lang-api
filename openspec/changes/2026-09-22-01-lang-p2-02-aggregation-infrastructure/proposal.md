## Why

第二阶段的 Dashboard、钱包和请求日志增强都需要一致的时间边界、受控分页、金额与日志转换、聚合保护和缓存隔离能力。现有基础用法接口各自处理时间与上游数据，且 `p2-2026-09-22-a` 基线仍存在数据量、夏令时和部分字段证据缺口，因此必须先建立可复用、可配置且失败语义明确的服务端聚合基础，避免下游重复实现或返回伪完整结果。

## What Changes

- 新增统一聚合查询上下文，校验带时区 ISO 8601 时间、IANA 时区、粒度与允许跨度，并始终按 `[startTime, endTime)` 和 UTC 执行。
- 新增稳定分桶与空桶补齐能力，正确处理自然日、夏令时及秒级边界。
- 新增受控上游分页读取器，以最大页数、最大记录数、单次调用超时和总预算阻止无界扫描；达到保护上限时明确失败，不返回部分结果冒充完整聚合。
- 集中承载已验证的日志类型、状态、Token、耗时和 quota/金额转换；未验证或条件可用的字段保持缺失语义，不被推断为零或确定值。
- 新增进程内短期只读缓存和同键并发请求合并；缓存键覆盖用户、规范化时间范围、粒度、时区和口径版本，且不保存会话、Access Token、完整 API Key 或原始敏感日志。
- 新增聚合上游调用数、扫描页数/记录数、耗时、缓存命中/合并和保护性拒绝的低基数观测信息。
- 将 P2-01 给出的保守保护值建模为环境隔离的 `.properties` 配置；30 天实时日志聚合默认拒绝，待补充性能证据后再显式调整。
- 不在本变更中新增 Dashboard、消费流水或模型目录业务接口，也不引入 Portal 数据库、共享缓存、消息队列或预聚合表。

## Capabilities

### New Capabilities

- `aggregation-query-infrastructure`: 定义第二阶段服务端聚合共用的时间范围、粒度与分桶、受控分页、转换、缓存/并发合并、配置保护和观测行为。

### Modified Capabilities

- 无。

## Impact

- 主要影响 `portal-api`：新增聚合基础包、New API 日志分页适配、配置属性、稳定错误映射及其单元/契约测试。
- 复用现有 `NewApiLogClient`、`QuotaMoneyConverter`、认证会话和统一错误包装，但公共聚合组件不直接向业务层暴露 New API 原始 DTO。
- 下游 LANG-P2-03、P2-05、P2-07 和 P2-09 将依赖本能力；本变更本身不改变现有公开 Portal API 路由。
- 口径固定引用 `p2-2026-09-22-a`；后续补齐 P2-01 外部证据时，通过显式基线/配置变更调整限制，不静默改变统计语义。
