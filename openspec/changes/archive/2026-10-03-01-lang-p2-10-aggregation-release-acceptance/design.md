## Context

动机见 proposal.md。P2-02 已实现查询保护、缓存和 Micrometer 聚合指标；P2-03 至 P2-08 的现行功能包含不可用与部分状态，并不代表原阶段目标全部满足。P2-09 最新真实证据证明特定本地版本的错误样本、扣费换算和日志字段，但未建立错误日志持续完整性或新的全局统计基线。

现行基线为 `p2-2026-09-22-a`，实时日志范围上限 168 小时。已有性能文档未冻结正常范围的 p95 目标，旧本地少量日志不能支撑容量承诺。详细结果以新验收报告为准，不沿用历史测试数量作为本次通过证据。

## Goals / Non-Goals

**Goals:** 将现有分散验证组织成可重复执行的检查集合，建立证据到构建及阶段需求的映射，真实反映可用、受阻和取消状态。

**Non-Goals:** 不修改业务 DTO 或统计口径，不添加预聚合数据库，不恢复取消字段，不扩展查询上限；不在本变更中自动修复所有历史受阻功能或执行生产发布。发现需要改变现行规范的缺口，报告并另行设计。

## Decisions

### 1. 分层入口和两份结论

在 `integration-tests/` 下增加验收入口，支持 `contract`、`local`、`performance`、`all` 检查集合，复用已有脚本与测试；运行编号仅用于报告关联。输出 JSON 与中文 Markdown，字段包括检查标识、范围、预期、实测、证据类型、状态、原因、证据位置和构建归属。失败优先退出码为 1，阻塞为 2，全部适用项通过为 0。

报告同时生成“所选现行契约检查”与“第二阶段上线条件”结论，部分集合不能覆盖完整集合结论。后者以阶段需求矩阵逐项判断，不能因为前者通过而 PASS。CANCELLED 仅引用已获用户取消的 P2-09 两项；其他缺口不可自行取消。这样可完成本变更中的工具开发任务，同时让外部证据任务继续未勾选，避免单一布尔结果掩盖阻塞。

### 2. 复用现有测试，补齐边界而不伪造真实证据

契约层使用可控数据源验证 0 条、单条、分页边界、上限与超限、多来源共享预算、超时恢复和错误不缓存。并发场景使用 10 个相同查询验证一次加载，再验证不同用户、范围、粒度、时区与基线版本隔离。10 是测试并发数，不是生产容量承诺。UTC、跨日与夏令时切换用固定时钟与数据验证；上游时区真实性缺失时另记 BLOCKED。

模拟传输仅用于契约和保护机制测试，明确标注为模拟；不向真实 New API 数据库写入伪造日志。真实环境复用专用身份和真实提供方调用脚本，缺少前提返回 BLOCKED。避免重复已有测试，只补充矩阵缺口，并澄清 `integration-tests/README.md` 中真实与模拟测试的边界。

浏览器覆盖四类页面的主流程、登录刷新、筛选与详情、适用异常状态及窄屏可用性。现行 null、partial、unavailable 也是需要验证的正确结果；协议和首 Token 延迟保留兼容空值但没有展示。

### 3. 性能测量先固定证据类型

支持的真实日志范围为 1h、24h、7d；30d 验证早期拒绝且无日志分页调用，不能算吞吐能力通过。冷查询在隔离测试进程中清理该测试缓存或等待过期，热查询在同一完整查询身份及 TTL 内执行，不清理共享业务缓存。

每个适用范围分别采集至少 20 次冷、热有效请求，记录规模、耗时、上游调用数、页数和异常，使用一致算法计算 p50/p95。小规模本地运行只能提供冒烟明细；模拟大数据只能说明保护和实现行为。典型规模数据、部署资源和性能目标由实施时的实际证据补齐；未冻结目标时可发布足量测量基线，但“性能达标”仍 BLOCKED。超时预算只说明何时终止查询，不能代替性能目标。

若出现超过现有容量边界的证据，提出后续预聚合评估，不直接放宽上限。选择这一方案而非预先引入存储，是因为目前没有真实容量证据支撑架构变更。

### 4. 运行构建指纹及有效配置

实施时从当前工作区生成 JAR 和前端资源，检查 JAR 静态资源与构建输出一致，核对运行容器的 JAR 摘要、镜像 ID、New API 版本与 digest；不能只凭镜像标签、启动时间或 Git revision 判断包含未提交改动。证据清单只保存非敏感配置，凭据不进入报告。

配置继续使用 `.properties`，显式核对公共、dev、test、prod 四份文件和环境覆盖后的值。当前预期如下，实施时发现漂移须报告原因而非偷偷调整：

| 配置 | 公共 / dev / prod | test |
| --- | --- | --- |
| 基线 | p2-2026-09-22-a | p2-2026-09-22-a |
| 分页大小 / 最大页数 / 最大记录 | 20 / 10 / 200 | 10 / 5 / 50 |
| 单次超时 / 总超时 | 5s / 30s | 1s / 5s |
| 实时日志上限 | 168h | 168h |
| 缓存 TTL / 最大条目 | 30s / 1000 | 5s / 1000 |

逐项确认 5 分钟、小时、日粒度跨度限制与实际继承，不把聚合时间桶跨度当作实时日志支持范围。不新增秘密配置或关闭保护以获得通过。

### 5. 观测与真实对账

复用 `portal.aggregation.duration`、`upstream.calls/pages/records`、`cache`、`rejections` 的既有指标，以进程内测试注册表和现有受控观测手段验证数值及标签。明确逻辑调用与实际 HTTP 尝试的区别，采样报告说明观测来源，不将测试指标冒充真实容器指标。不开放 `/actuator/metrics` 或新增公开端点。

真实对账固定用户、左闭右开时间范围、时区、筛选和基线；比较已验证的 Token、日志字段、可用汇总及定价，金额使用精确十进制。趋势、TOPUP、REFUND、完整请求数与成功率缺来源时保留 BLOCKED。P2-09 中 `quota_per_unit=500000` 和特定 type=5 样本作为新证据关联；默认错误日志关闭等完整性限制仍须显式记录，不自动变更旧基线。

凭据通过运行时输入提供，禁止输出 Cookie、令牌和原始负载。原始探测结果仅进入既有忽略目录 `portal-api/target/probe-raw/`，不提交；持久化采用白名单投影，并复用现有敏感扫描器核验。真实本地流程若临时修改错误日志开关或创建测试密钥，记录开始状态并在结束或失败时恢复和清理，不删除持久卷。

### 6. 阶段矩阵与恢复文档

报告逐项映射 P2-01 至 P2-10：原目标、现行契约、历史证据、新证据、未满足条件及解除阻塞所需行动。更新阶段文档中协议与首 Token 延迟的残留要求，但不将其他受阻项推定为取消。基线版本升级或启用受阻能力必须另有设计与验证。

提供 New API 升级前后回归清单，包含版本、日志字段、错误完整性、分页、时区、定价和换算证据；提供应用旧镜像恢复、配置恢复、缓存失效和功能复测步骤。恢复方案保持原数据库和卷，不使用 `down -v`。发布步骤仅为文档，不在验收命令中执行部署。

## Risks / Trade-offs

- 典型规模和上游证据暂缺 → 工具可实施，相关验收任务保留 BLOCKED，不承诺本变更即可解除全部阶段阻塞。
- 历史性能与口径文档存在旧结论 → 保留历史来源与日期，新增证据明确适用版本；基线变更另行推进。
- 容器与本地资源不一致 → 在真实页面和性能采样前执行构建一致性检查，不复用旧镜像通过结果。
- 对账期间上游数据持续变化 → 使用固定结束时间及完整筛选；无法得到稳定快照时记录限制与阻塞，不强行比较。
- 外部提供方存在费用或不稳定 → 使用既有受控最小调用流程；确定性保护测试使用模拟数据，真实与模拟证据分别呈现。

## Migration Plan

本变更不迁移业务数据。按契约入口、真实本地环境、性能采样、阶段报告的顺序实施；正常构建与检查完成后保留未提交修改。若只完成工具或小样本验证，明确报告部分完成，不将整个 P2-10 或第二阶段标为已完成。
