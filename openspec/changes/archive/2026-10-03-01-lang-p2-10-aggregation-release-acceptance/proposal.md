## Why

LANG-P2-09 已按取消协议和首 Token 延迟后的范围归档，下一项为 LANG-P2-10：性能、安全、端到端验收与上线收口。当前各能力的验证记录分散，部分上游口径和真实容量仍受阻，需要可复现的验收入口与证据报告，避免把本地测试通过误判为第二阶段整体具备上线条件。

## What Changes

- 新增第二阶段聚合验收入口，分别执行契约、安全、真实本地环境和性能验证，输出机器可读结果及中文报告。
- 覆盖时间范围、分页与总预算、缓存与并发加载、用户隔离、异常恢复，以及 Dashboard、钱包、模型和请求日志的现行用户流程。
- 将每项结果区分为 PASS（通过）、FAIL（不符合契约）、BLOCKED（缺少前提或证据）和 CANCELLED（用户明确取消）；分别给出现行能力验收结论和第二阶段上线条件结论。
- 记录被测 JAR、镜像、前端资源、New API 版本和有效配置，复用现有聚合指标验证观测能力，不新增公开监控接口。
- 对真实数据进行抽样对账，整理性能证据、运行限制、升级回归、恢复与回滚说明；同步阶段文档中的取消项与剩余阻塞。
- 不恢复 P2-09 已取消的协议、首 Token 延迟展示，不自动开放 30 天实时日志查询，不自动改变统计基线或将不可用金额、请求总数和成功率改为可用。

## Capabilities

### New Capabilities

- `aggregation-release-acceptance`: 聚合能力验收入口、证据归属、性能与安全检查、真实环境对账、上线条件判定及可复现报告。

### Modified Capabilities

无。现有业务接口、不可用状态和保护规则保持其当前规范；发现行为变更需求时另行设计变更。

## Impact

- 预计涉及 `integration-tests/` 验收脚本、后端聚合契约测试、前端端到端测试及验收文档，不引入新的数据库、消息队列或监控平台。
- 核对四份后端 `.properties` 配置的有效值及环境继承，不以提高查询上限规避验收失败。
- 实施阶段需要受控本地 Docker 环境和专用测试身份；典型规模数据及部分上游证据不足时保持 BLOCKED，不伪造生产容量结论。
- 参考 `docs/11_第二阶段聚合能力开发与子需求拆分.md`、`docs/new-api/第二阶段聚合性能基线.md`、`docs/new-api/第二阶段统计与流水口径.md` 及 P2-09 归档证据。
- 本变更设计与后续验收均不包含 Git 提交、发布或生产部署。
