## Purpose

为第二阶段聚合能力提供可复现的验收入口与证据报告，覆盖保护机制、安全隔离、用户流程、真实数据对账和性能测量。明确区分现行功能验证结果与整体上线条件，避免缺少上游证据或典型规模数据时产生错误的完成结论。

## ADDED Requirements

### Requirement: 验收入口与结果判定

验收工具 SHALL 支持分别执行契约、本地真实环境、性能检查及完整检查，输出结构一致的 JSON 和中文报告。每项 MUST 包含检查标识、证据类型、预期、实测结果、PASS/FAIL/BLOCKED/CANCELLED 状态、原因和证据位置；缺少必需配置、身份、数据或环境 MUST 为 BLOCKED，不能静默跳过。选定检查集合的进程退出码 MUST 为全部适用项通过时 0、存在 FAIL 时 1、无 FAIL 但存在 BLOCKED 时 2；完整检查 MUST 包含所有必需检查，CANCELLED 必须引用用户明确取消的依据。

#### Scenario: 缺少真实环境凭据
- **WHEN** 执行包含真实环境验证的检查集合但未提供专用测试身份
- **THEN** 对应项为 BLOCKED，报告指出缺失前提，进程不能返回通过

#### Scenario: 检查存在失败及阻塞
- **WHEN** 同一次执行同时出现 FAIL 和 BLOCKED
- **THEN** 报告保留两类结果，进程返回 1

### Requirement: 证据必须绑定被测构建

真实本地环境报告 MUST 记录时间、环境、配置档案、应用 JAR 摘要、运行镜像标识、前端资源一致性结果、New API 版本及镜像摘要、统计基线版本和不含秘密的有效保护配置。MUST 验证运行构建与本次待验收产物一致；旧镜像测试或无法确认一致性的测试不能证明本次改动通过。

#### Scenario: 运行镜像未包含本次产物
- **WHEN** 容器中的 JAR 或前端资源与待验收产物不一致
- **THEN** 构建一致性检查为 FAIL，并阻止本次产物获得真实环境通过结论

### Requirement: 查询保护及缓存隔离验证

验收 MUST 覆盖 1 小时、24 小时、7 天的现行查询规则及 30 天实时日志拒绝规则，验证分页、记录数、单次超时、总预算、失败后恢复、同查询并发加载、缓存命中与过期。MUST 覆盖不同用户、范围、粒度、时区和基线版本之间的缓存隔离，以及时间区间左闭右开、跨日和夏令时边界；受保护或上游失败的查询不能输出看似完整的成功统计。

#### Scenario: 不支持的 30 天实时日志范围
- **WHEN** 查询超过现行实时日志范围上限
- **THEN** 请求按现行规范拒绝且不发起日志分页调用，报告记录保护通过而非 30 天容量通过

#### Scenario: 相同查询并发访问及用户变化
- **WHEN** 同一身份并发发起相同查询，另一身份发起相同范围查询
- **THEN** 同身份共享一次加载，另一身份的数据与缓存不能混入，并验证加载失败后可重新请求

### Requirement: 安全与现行页面流程验收

验收 MUST 覆盖未登录访问、跨用户访问、非法时间与时区、非法模型标识及敏感信息泄漏检查，并通过浏览器验证 Dashboard、钱包、模型目录与详情、请求日志的主流程和适用的加载、空数据、失败、不可用、部分数据及登录刷新状态。协议和首 Token 延迟展示 MUST 保持取消；兼容字段为空不能导致页面异常。

#### Scenario: 不可用金额或部分流水
- **WHEN** 上游证据不足使金额不可用或流水不完整
- **THEN** 页面准确展示现行不可用或部分状态，不以零金额或完整流水代替

#### Scenario: 取消的请求日志指标
- **WHEN** 浏览器展示请求日志且兼容字段为 null
- **THEN** 不显示协议和首 Token 延迟，其他现行字段可正常查看

### Requirement: 真实数据对账与性能证据分类

验收 MUST 对真实日志、可用聚合指标、趋势、流水和模型定价进行适用的抽样对账，固定身份、时间范围、时区、筛选与基线；缺少权威来源的项目 MUST 保持 BLOCKED。模拟数据、真实小样本与典型规模真实数据 MUST 分开标识。性能报告 MUST 分开记录冷查询和缓存命中、数据规模、耗时、上游调用与分页数、错误及保护触发；只有适用范围具备代表性数据且冷、热查询各至少 20 次有效样本时，才能发布该范围的 p50/p95 性能基线。MUST 不把超时预算当作已冻结的性能目标，不把拒绝耗时当作容量结论。

#### Scenario: 本地只有少量日志
- **WHEN** 本地真实数据不足以代表目标规模或有效样本不足
- **THEN** 可以报告实测明细和冒烟结果，典型规模性能验收为 BLOCKED，不能宣称容量达标

#### Scenario: 错误日志存在但未证明完整
- **WHEN** 获得真实 type=5 样本但未证明部署环境持续、完整记录错误日志
- **THEN** 记录样本证据，不能据此宣称请求总数或成功率的完整口径成立

### Requirement: 观测与证据安全

验收 MUST 验证聚合耗时、上游调用与分页、缓存命中和保护拒绝可以被观察，并说明指标计数对象；MUST 不新增公开的指标或配置端点。可持久化报告和样本 MUST 去除密码、令牌、Cookie、Authorization、上游密钥、原始请求和响应内容及用户身份信息，并通过仓库既有敏感扫描规则；指标标签 MUST 不包含用户标识、密钥、请求标识等敏感或无限增长的值。

#### Scenario: 样本包含敏感字段
- **WHEN** 准备持久化的报告或样本被扫描发现敏感信息
- **THEN** 持久化验收为 FAIL，修复脱敏后才能保存为验收证据

### Requirement: 上线条件与阶段状态必须单独判定

报告 MUST 分别提供现行契约验收结果和第二阶段上线条件结果，并列出原阶段需求对应的通过、失败、阻塞或取消依据。原有 Dashboard、钱包、模型元数据、30 天查询及典型规模性能的未满足条件 MUST 保留；本地错误与扣费样本不能自动更新冻结统计基线或解除其他需求阻塞。仅当全部未取消的必需上线条件有有效证据且无 FAIL/BLOCKED 时才能声明第二阶段满足上线条件。文档 MUST 提供版本升级回归、运行限制、失败恢复、构建回退步骤与尚缺证据清单，执行验收不等于授权发布。

#### Scenario: 现行不可用行为验证通过
- **WHEN** 当前页面按规范展示不可用状态但原阶段目标仍缺上游口径
- **THEN** 现行契约项可以 PASS，对应原阶段上线条件仍为 BLOCKED

#### Scenario: 本地扣费证据补齐
- **WHEN** 本地获得 quotaPerUsd 的独立证据但冻结基线及其他来源未完成更新验证
- **THEN** 报告关联新增证据并列明差距，不直接改动统计基线或启用原受阻能力
