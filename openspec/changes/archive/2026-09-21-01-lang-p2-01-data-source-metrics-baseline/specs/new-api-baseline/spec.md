## ADDED Requirements

### Requirement: 第二阶段聚合接口兼容性矩阵完整
项目 SHALL 在冻结版 New API 上对 `/api/log/self`、`/api/log/self/stat`、`/api/data/self`、`/api/user/self`、`/api/user/topup/self` 和 `/api/pricing` 建立第二阶段兼容性矩阵。每个接口 MUST 记录路由、方法、认证要求、请求参数、分页与时间边界、成功/空数据/失败响应、前置配置、实测日期、冻结版本、样例引用和结论状态；对协议、TTFT、退款等不一定存在的能力 MUST 明确记录验证结果。

#### Scenario: 查询第二阶段聚合依据
- **WHEN** LANG-P2-02 至 LANG-P2-09 设计聚合、流水、模型或日志增强能力
- **THEN** 每项使用的数据都能追溯到冻结版接口矩阵和脱敏样例，差异、条件或不可用原因不会被误写成已支持

#### Scenario: 覆盖成功与边界响应
- **WHEN** 某接口被标记为 `已验证`
- **THEN** 至少存在与其适用行为相符的成功或非空、空数据、失败和参数边界证据，无法构造的场景被明确记录为证据限制

#### Scenario: 外部条件不具备
- **WHEN** 退款、支付方式、模型供应商或足量历史数据因测试环境条件无法真实验证
- **THEN** 对应能力标记为 `条件可用` 或 `不可用`，并记录缺失条件，不以源码、旧 fixture 或字段名称替代真实运行证据

## MODIFIED Requirements

### Requirement: 实测证据安全且可重复
接口实测 SHALL 在隔离环境对冻结镜像执行，并保存可重复的环境前置条件、数据准备、探测步骤、HTTP 状态、关键响应结构、测量元数据和脱敏样例。第二阶段六个数据来源 MUST 覆盖成功或非空、空数据、失败和参数边界；无法构造的场景 MUST 明确记录原因与结论限制。证据 MUST NOT 包含真实密码、Session、Cookie、Access Token、完整 API Key、供应商密钥、数据库凭据、支付签名、可识别个人信息或未裁剪的请求内容。

#### Scenario: 保存认证成功样例
- **WHEN** 探测登录或其他会返回凭证的接口
- **THEN** 兼容性证据保留字段结构和 Cookie 属性，但所有凭证值均被稳定占位符替换

#### Scenario: 保存日志和账户样例
- **WHEN** 探测日志、用量、当前用户、充值或价格接口
- **THEN** 用户名、邮箱、手机号、IP、完整 Key、请求内容、内部渠道和供应商信息被删除或稳定替换，同时保留验证字段语义所需的结构、类型和边界值

#### Scenario: 重跑接口探测
- **WHEN** 使用相同冻结镜像、已记录前置配置和确定性测试数据重新执行探测
- **THEN** 能判断接口是否仍符合记录的路由、方法、认证、参数边界、关键响应结构和字段语义

#### Scenario: 脱敏后无法证明字段关系
- **WHEN** 删除敏感值会破坏验证状态映射、关联关系或稳定 ID 所需的证据
- **THEN** 使用同一轮探测内一致的不可逆占位符保留关系，不保留原值或可逆映射表

### Requirement: New API 升级受兼容性门禁控制
冻结后的 New API 升级 SHALL 作为独立变更处理。升级前 MUST 记录目标版本、迁移说明、备份与恢复点，并对第一阶段兼容性矩阵、第二阶段聚合接口矩阵、字段来源与口径基线及数据持久化场景重新验证；不得仅修改 tag 或 digest 后直接视为升级完成。只有受影响项目重新获得实测结论并完成口径版本处理后，升级才可进入生产验证。

#### Scenario: 提议升级冻结版本
- **WHEN** 需要从当前基线升级到新 Release
- **THEN** 在变更生效前完成数据库备份、迁移风险记录、必需接口回归、聚合字段与性能基线对比以及失败恢复验证

#### Scenario: 字段语义或性能发生变化
- **WHEN** 新版本保持接口可调用但改变日志类型、状态、单位、时间边界、字段可空性或查询成本
- **THEN** 对应聚合基线不得沿用旧版本结论，必须记录差异并发布新的口径版本或阻止升级

#### Scenario: 升级验证失败
- **WHEN** 必需接口、聚合数据契约、数据库迁移或数据一致性验证失败
- **THEN** 保持当前冻结基线不变，并记录失败证据和恢复结果
