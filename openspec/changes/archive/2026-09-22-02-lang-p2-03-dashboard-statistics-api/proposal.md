## Why

P2-02 已提供有边界的时间、分页、聚合和缓存基础，但 Dashboard 仍依赖第一阶段 `/usage/**` 接口，无法用单一稳定契约返回六项指标、趋势和最近请求。现在需要在不放大 P2-01 未验证结论的前提下建立正式 Dashboard 聚合接口，让后续 P2-04 只负责页面展示与下钻。

## What Changes

- 新增受保护的 `GET /portal/api/dashboard/stats`，只接受必填 `startTime`、`endTime`、`granularity` 和 `timezone`，不接受 `1H`、`7D` 等页面快捷范围。
- 响应返回规范化查询范围、服务端口径版本、六项指标、请求趋势、消费趋势和最多 10 条最近请求。
- 每项指标和趋势均返回机器可读的可用性与原因；当前 `p2-2026-09-22-a` 下仅 Token 用量、活跃 Key 和平均延迟可作为确定值，请求总数、消费总额、成功率及两类趋势保持 `null`/不可用，不回填零或估算值。
- 空数据时，已验证的可加指标返回确定零值；无分母的平均延迟返回 `null + NO_DATA`，避免把“无请求”解释为零延迟。
- 最近请求只返回用户自有、经过裁剪的 Portal DTO，按稳定顺序限制为 10 条；不返回渠道、节点、token ID、供应商信息、原始响应或完整凭证。
- 所有结果从同一次受控日志快照计算，共用 P2-02 的范围校验、7 天实时扫描、10 页/200 条、30 秒总预算、用户隔离缓存和低基数观测。
- 保护上限、分页不一致或上游失败时整个接口明确失败，不返回指标与趋势来自不同数据快照的部分成功结果。
- 当前无 30 天实时性能证据，30 天日志查询继续稳定拒绝；只有 P2-01 发布新证据或另行批准预聚合方案后才能放宽，P2-03 不绕过该门禁。
- 不修改 Dashboard 前端，不移除或改变第一阶段 `/portal/api/usage/**` 接口；页面迁移属于 LANG-P2-04。

## Capabilities

### New Capabilities

- `dashboard-statistics`: 定义 Dashboard 聚合查询参数、六项指标及可用性、趋势、最近请求、认证隔离、错误和缓存行为。

### Modified Capabilities

- 无。

## Impact

- 主要影响 `portal-api` 的 `web/dashboard` 查询、DTO 和控制器，复用已归档 P2-02 提供的 `base/aggregation`、受控日志读取、Caffeine 缓存和 Micrometer 观测。
- 新增公开只读路由 `/portal/api/dashboard/stats`，继续使用统一 `{requestId,data}` 与既有错误目录，不新增写操作或 CSRF 例外。
- 不新增第三方依赖、数据库、共享缓存或配置文件格式；最近请求数量采用固定契约上限，不新增环境配置。
- 新增接口说明和契约测试；现有 Dashboard 前端及 `/portal/api/usage/**` 保持兼容，直到 P2-04 显式迁移。
- LANG-P2-03 的 30 天验收仍受 P2-01 性能证据缺失约束；实现可以完成受支持范围，但不得在该外部条件未解决时把 30 天能力宣称为已完成。
