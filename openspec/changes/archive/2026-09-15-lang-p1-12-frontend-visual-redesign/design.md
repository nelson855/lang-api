## Context

参见 [proposal.md](./proposal.md) 的动机说明。本项目是 React 19 + React Router 7 + TanStack Query 的单页应用，使用 Tailwind CSS 4 的 CSS 驱动主题、独立 CSS 模块式样式文件、Radix Dialog、React Hook Form/Zod、i18next、Lucide 图标以及本地打包的 Manrope 与 JetBrains Mono 字体。

现有 `tokens.css` 已是运行时颜色和尺寸的集中来源，并由测试禁止功能样式中出现硬编码十六进制颜色；`Button`、`Input`、`FormField`、`Dialog`、`DataTable`、`Pagination`、反馈状态和 Toast 已形成共享基础。项目已建立 `DESIGN.md` 和 `UX-CONTRACT.md`，本次将其与浅色系统同步。页面业务行为已有较完整的 OpenSpec、单元/组件测试、axe 检查和 Playwright 场景，因此此次设计将视觉系统整体替换，但把现有业务与安全行为视为必须保留的权威契约。

本次包含营销型公开页面与产品型控制台两种 register：公开页面允许更强的品牌表达；认证和控制台以任务清晰、状态稳定与长期使用为先。参考 QinghuaAPI 仅用于确认“克制、留白、清楚”的方向，不复制其黑白配色、居中大标题、四卡片卖点、三步图标流程和导航比例。

## Goals / Non-Goals

**Goals:**

- 建立可持续维护的 Clear Circuit 视觉决策、运行时令牌映射和跨屏行为契约。
- 先强化共享组件，再迁移所有现有路由，保证同一发布版本内不出现新旧主题混用。
- 让公开首页具有可识别但克制的“路由轨迹”技术签名，让控制台在浅色环境中保持清晰、紧凑且耐久。
- 缩减搜索、筛选与登录/注册表单的控件体积，防止桌面端输入框过高或无意义铺满。
- 保留并验证认证、密钥风险操作、余额与用量、分页、局部失败、会话失效、真实数据和法律内容等既有行为。
- 让桌面、320 像素窄屏、键盘、200% 缩放、减少动效和强制颜色场景都有明确落地方式。

**Non-Goals:**

- 不新增后端接口、数据字段、统计维度、图表数据、充值能力、模型能力、用户角色或管理后台。
- 不新增用户主题切换；Clear Circuit 是本阶段唯一产品主题。
- 不引入完整 UI 框架、动画框架、图表框架、远程字体、远程图片或虚构营销数据。
- 不改变既有路由、Portal API、认证/会话、密钥安全、支付关闭策略、法律正文和 SEO 发布规则。
- 不在该变更中修改 `AGENTS.md`，也不执行 Git 提交、发布或部署。

## Decisions

### 1. 采用“共享身份、双重密度”的混合 register

公开站、认证页和控制台共享颜色语义、字体、焦点、控件、状态、图标和动效语言，但不共享同一页面密度：

- 公开站使用宽松的垂直节奏、较大的中文标题和 1180px 内容容器，负责解释产品与引导开始。
- 认证页使用单一聚焦面板，保留品牌、返回首页、注册/登录互链与法律入口，表单宽度不超过 420px，标准控件高度为 40px，不添加未实现的第三方认证。
- 控制台使用约 240px 常驻侧栏、约 60–64px 顶部上下文栏和更宽的业务内容区域；卡片、筛选器、表格和表单采用舒适但紧凑的产品密度。

选择该方案是因为全站使用同一营销式大标题会降低控制台效率，而公开区与控制台完全分离两套视觉又会削弱品牌连续性。两者通过相同令牌和组件保持同源，通过留白和密度体现使用场景差异。

### 2. Clear Circuit 以六个核心视觉角色为基础

`tokens.css` 继续作为运行时令牌的权威来源（Token Mapping Model B），项目根级 `DESIGN.md` 镜像被接受的精确值并解释用途，不从文档生成 CSS。核心方向值为：

| 名称 | 值 | 主要用途 |
|---|---|---|
| Canvas | `#F4F7FB` | 页面画布与控制台工作区 |
| Paper | `#FFFFFF` | 卡片、表单和数据表面 |
| Mist | `#E9EEF5` | 悬停、选中和次级区域 |
| Graphite | `#182235` | 主文字和高对比图标 |
| Slate | `#5D6B82` | 次级文字与辅助标签 |
| Cobalt | `#315BE8` | 品牌主操作、焦点、当前项和关键链接 |

运行时仍需从上述核心色扩展边框、遮罩、禁用及 `info / success / warning / danger` 语义角色。成功、危险和警告不得复用 Cobalt；语义状态必须同时提供文字、图标或形状。全部颜色只在令牌文件出现，共享组件和页面只消费语义变量。

`DESIGN.md` 将记录：Clear Circuit 的 North Star、QinghuaAPI/New API 默认面板/赛博霓虹/通用蓝色 SaaS 渐变为反向参考、混合 register、颜色与字体、间距、圆角、层级、图标、动效、数据可视化、内容语气及组件状态。创建后运行官方 `designmd lint`，并维护从 `DESIGN.md` 到 `tokens.css`、Tailwind `@theme` 和共享组件的映射表。

### 3. 字体与内容通过“中文主叙事、技术文本等宽化”建立识别

- Manrope 继续负责英文、数字和拉丁标题骨架，不新增远程字体。
- 中文使用 `PingFang SC`、`Microsoft YaHei`、系统 sans-serif 回退，保证 macOS 与 Windows 可读性；不额外引入体积较大的中文 Web Font。
- JetBrains Mono 只用于代码、请求 ID、模型 ID、路径、价格/用量等需要精确对齐的技术信息。
- 中文主标题和按钮使用自然中文；英文仅用于品牌、协议、模型、代码、路径和短技术标签。英文界面使用独立完整文案，不做中文逐字拼接。
- 重要说明、错误和操作不截断；标识符需要保持行高时可单行截断，但必须通过聚焦、复制或展开方式获取完整值。

该策略保留本地资源和构建稳定性，同时让科技感来自信息本身，而不是依赖装饰字体或英文营销口号。

### 4. 首页采用 B2 非对称快速接入结构

首页首屏左侧为中文价值主张、简短说明与两个真实操作，右侧为快速接入终端。终端只展示根据 public-config 生成的 Base URL、标准代码模板和协议可用状态，不展示虚假的 `200`、延迟、Token 数或“实时请求已连接”。

首屏之后按以下顺序组织：

1. 当前真实开放的协议与产品能力摘要；
2. 从模型接口读取的模型目录摘要及前往完整目录入口；
3. “创建账户 → 生成 API 密钥 → 替换 Base URL”的真实三步流程；
4. 根据认证、注册和发布状态计算的最终行动入口；
5. 结构化页脚。

模型摘要是独立查询区域，具备加载、空、失败和重试状态，失败不影响首屏。`PREVIEW`、无协议和注册关闭时复用相同几何，但改为准确状态说明和可到达操作。

曾考虑居中主张配请求轨迹（B1）与模型轨道主视觉（B3）。B1 更有独特性但信息效率较低；B3 装饰与动画更重。最终选择 B2，并以不对称比例、终端状态细节和中英文排版建立区别，符合用户已确认的简洁优先。

### 5. 控制台采用稳定侧栏和明度分层，不复用首页氛围

桌面控制台的常驻侧栏负责一级导航与账户区域，顶部栏负责当前位置和少量全局状态，页面标题区负责页面级说明与主要操作。侧栏使用比画布略深的冷灰表面，当前项使用低饱和 Cobalt 背景/文字组合，不使用大面积高亮。

Dashboard 将余额、区间摘要和趋势保持为独立查询面板。现有趋势数据优先使用轻量 SVG/CSS 图形或结构化列表的视觉增强，不因设计稿而引入图表框架；图形必须有同等文本值或表格语义。不存在的数据维度（例如模型用量占比、同比或成功率）不得因为概念稿而新增或伪造。

API 密钥、请求日志和充值记录沿用现有服务端分页与真实数据。桌面保留语义 `<table>`；窄屏按当前记录是否需要跨行比较，继续使用已有卡片表示或表格自身横向滚动。工具栏、表格和分页形成完整数据区域，但页面主滚动仍由文档/控制台内容区拥有；不得为表格在共享壳上设置 `100vh` 或 `overflow: hidden`。

### 6. 共享组件先于页面迁移，Canonical UI Map 固化在 UX-CONTRACT

实现开始时新增项目根级 `UX-CONTRACT.md`，从当前主规格、测试和已验证流程提取行为，不重新发明业务规则。另新增 `premium-ui.json`，声明 `product-admin` profile、源码根、Canonical Map、必需能力、验证命令和证据路径。

适用能力的所有者如下：

| 能力 | Canonical owner | 决策 |
|---|---|---|
| Button / IconButton | 共享 `Button` 体系 | 从单轴 variant 迁移为 emphasis + intent 的可组合语义，保留兼容映射直至所有调用迁移 |
| Form / validation | `FormField` + React Hook Form/Zod 或现有等价表单适配 | 所有产品表单 `noValidate`；错误关联、首错聚焦、重复提交与服务端恢复一致 |
| Password / secret | 新增共享 `PasswordField`/`SecretField` | 默认遮蔽，可访问显示/隐藏；API Key reveal 继续遵守现有清理规则 |
| Search | 新增共享 `SearchField` | 非空时显示可访问清除按钮；本地筛选即时，显式远程查询保留提交行为，不擅自改为自动搜索 |
| Select/Listbox | 基于 Radix Select 的共享组件 | 视觉和弹层几何由应用拥有；新增单个 Radix Select 依赖，不手工实现 ARIA |
| Date/time | 共享 Input 的原生 `datetime-local` 变体 | 明确接受平台拥有弹层；保持现有存储/解析语义，不在本次引入日历组件 |
| Dialog / drawer | 现有 Radix Dialog | 分离普通 Dialog、风险 AlertDialog 和移动导航 Drawer 的业务命名变体；统一层级、焦点、滚动和尺寸 |
| Toast / status | 现有 ToastProvider 与反馈组件 | 保留当前四种语义，补充稳定位置、去重和浅色状态，不把关键错误只放在 Toast |
| DataTable / pagination | 现有共享组件 | 保留语义表格与服务端分页；补足标题、状态区域、稳定边界和窄屏策略 |
| Scrollbar | 全局应用样式 | `scrollbar-color/width` + WebKit fallback，组件类只表达稳定 gutter 等几何例外 |
| CRUD / 风险操作 | `UX-CONTRACT.md` + 既有 API Key 流程 | 创建、编辑、启停、删除、reveal 的 pending、结果、错误、焦点和敏感值清理保持不变 |

按钮 API 的兼容映射只作为迁移工具，所有页面完成后移除旧 variant 别名，防止新旧语义长期并存。

### 7. 状态、层级和动效由全局合同管理

- 加载默认使用稳定预留区域中的应用自有 Spinner；不引入大面积 Skeleton。后台刷新保留旧内容，局部失败只替换所属面板。
- 统一层级变量：sticky、dropdown、popover、header、backdrop、dialog、drawer 和 toast；禁止页面局部任意大数值 `z-index`。
- 对话框保持标题和操作可达，正文过长时仅 body 内滚动；严重风险确认初始聚焦安全操作，提交 pending 时不提前关闭。
- 全局滚动条覆盖产品自有滚动区，保留可见轨道/滑块、hover/active、稳定 gutter 和 forced-colors 回退。
- 普通微交互控制在约 160–220ms，主要使用颜色、边框和轻微透明度；仅首页快速接入终端允许一次轻微入场或倾斜。`prefers-reduced-motion: reduce` 下取消位移、倾斜、缩放和错峰，只保留不超过 100ms 的透明度或即时状态。

不引入动画框架，因为现有 CSS 足以实现需要的克制动效，新增依赖与复杂度没有收益。

### 8. 按风险和依赖顺序迁移，但最终作为统一主题交付

变更在同一开发分支中分阶段完成并保持每阶段可测试：

1. 建立 `DESIGN.md`、`UX-CONTRACT.md`、`premium-ui.json`、令牌与全局基础；
2. 强化 Button、Input、PasswordField、SearchField、Select、Dialog、Toast、DataTable、Pagination 和状态组件；
3. 迁移 Public/Auth/Console 三类布局与品牌资产；
4. 优先迁移认证、个人设置和 API Key 等敏感/风险流程；
5. 迁移 Dashboard、请求日志、钱包等数据页面；
6. 迁移首页、模型、文档、服务地区、法律和错误页面；
7. 删除旧样式与兼容别名，执行完整验证。

这种顺序避免页面先自行实现临时样式，也优先保护安全敏感流程。用户可见发布应在全部现有路由迁移完成后进行，避免新旧主题并存。若上线前必须回退，只回退前端静态资源到上一个已验证构建；后端与数据无需回滚。

## Risks / Trade-offs

- **[浅色表面过多可能显得平淡或模板化]** → 用冷调画布与白色工作面的层级、精确边框和首页路由轨迹建立识别，不使用通用蓝紫渐变。
- **[钴蓝同时承担品牌与信息可能造成语义混淆]** → 品牌主操作与 success/warning/danger 使用独立语义色，并用文字或图标补充。
- **[全站迁移范围大，容易出现局部旧样式]** → 先固化令牌和共享组件，再按完整工作流迁移；使用旧色/裸控件/硬编码守卫与代表性页面截图阻止遗漏。
- **[新增 Select 组件可能改变表单交互]** → 只替换现有单选下拉，保留值、提交时机和查询行为；使用成熟 Radix primitive，并覆盖键盘、弹层、焦点、长选项、窄屏和 200% 缩放测试。
- **[概念稿中的数据超出现有接口]** → 视觉稿仅表达布局，实施只渲染现有接口字段；不存在的成功率、同比、模型占比和真实请求延迟不得实现或静态填充。
- **[中文系统字体在平台间度量不同]** → 使用明确回退栈、弹性布局、允许换行和长文案测试，不以固定字符数控制容器。
- **[大面积 CSS 调整引发特异性冲突]** → 全局样式只负责 reset、令牌、排版、焦点、滚动条和通用容器；组件与页面样式保持低特异性并由共享组件控制状态。
- **[视觉重构意外改变高风险行为]** → `UX-CONTRACT.md` 从现有规格与测试提取，不使用视觉稿重写业务；认证、密钥、余额、法律和会话失败场景在迁移前后跑同一行为测试。

## Migration Plan

1. 对现有路由、令牌、共享组件、Select/date/form/scrollbar/Toast/CRUD 所有者建立清单，并把权威行为来源记录到 `UX-CONTRACT.md`。
2. 创建并校验 `DESIGN.md`，采用运行时令牌为权威的映射模型；在 `tokens.css` 一次性完成语义令牌切换，并保留构建可用。
3. 新增或强化共享组件及组件状态测试；只有共享基础稳定后才迁移页面。
4. 按“高风险流程 → 数据页 → 公开内容页”迁移完整工作流，并在每个切片后运行相关单元/组件/axe 测试和浏览器检查。
5. 全部页面迁移后移除旧颜色、页面局部基础控件样式与兼容别名，运行品牌扫描、令牌守卫、OpenSpec 严格校验、Premium 静态审计、完整前端测试和生产构建。
6. 用真实浏览器验证中文/英文、桌面、320px、200% 缩放、键盘、Select 打开状态、减少动效、加载/空/错误/结果未知、会话失效和风险确认。
7. 保留全部改动未提交，报告测试结果与 `git status`，由用户决定是否提交或发布。

回滚不涉及数据迁移。若新前端在发布前验证失败，恢复到上一个已验证前端构建并继续修正；不得通过保留新旧两套主题运行时开关形成长期分叉。
