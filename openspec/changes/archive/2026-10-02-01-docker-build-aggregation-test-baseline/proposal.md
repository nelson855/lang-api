## Why

当前 Docker 镜像构建会执行根 Maven 完整测试，但被既有聚合测试桩的架构规则冲突、范围夹具失效，以及容器内无法定位仓库根目录的证据夹具阻塞。P2-07 的目录实现和真实扣费验证无法通过正常本地 Compose 链路进入运行态。

修复后的首次 Docker 重建取得真实前端失败：Dashboard 测试在整页用 `/1\.0/` 查找余额，时间戳秒数末位为 1 时也匹配 `01.000` 等文本，产生多个匹配。该问题是同一正式构建入口的测试稳定性阻塞，纳入本变更，不修改业务接口。

## What Changes

- 固定能复现碰撞的时钟，先证明 Dashboard 余额断言失败，再将查询限定到当前余额区域；保留全部前端测试与非致命警告。
- 修复聚合测试桩与 Web 层架构规则之间的边界，使测试辅助类型不被当作生产 Web 返回类型。
- 修正聚合范围纵向测试的夹具构造，使其能够覆盖“服务端在访问上游前拒绝超范围”的实际行为。
- 使聚合证据夹具测试在 Docker 构建工作目录中仍能以只读方式定位已复制的仓库文件，且不放宽敏感信息扫描或基线校验。
- 验证根 Maven 构建与本地 Compose 构建在干净环境中均可完成，保留“测试失败阻止打包”的既有规则。

## Capabilities

### New Capabilities

无。本变更只修复现有构建和测试实现，不引入新的对外可观察行为。

### Modified Capabilities

无。`integrated-application-build` 与 `local-compose-environment` 已要求正式构建和 Compose 启动成功；本变更不改变这些需求，只恢复其实现符合性。

## Impact

- 受影响范围：聚合测试辅助代码、测试夹具定位逻辑、Docker 构建上下文或测试运行配置。
- 不修改 Portal 对外 API、模型目录契约、New API 配置、持久化数据或生产运行镜像的最小化要求。
- 验证范围：聚合相关测试、完整 Maven 构建、`docker compose ... build lang-api` 与 P2-07 的运行态目录接口验证。
