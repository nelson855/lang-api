## Purpose

为第二阶段各业务聚合提供统一、可验证且有成本边界的查询基础，使时间解释、上游分页、字段可用性、缓存隔离和失败语义不再由各接口重复决定。

## ADDED Requirements

### Requirement: 聚合查询使用统一且明确的时间上下文
系统 SHALL 要求聚合查询同时提供带偏移量的 ISO 8601 `startTime`、`endTime`、IANA `timezone`、稳定 `granularity` 和口径版本，并在任何上游访问前完成校验。时间范围 MUST 按秒级精度和 `[startTime,endTime)` 解释，内部运算 MUST 使用 UTC；开始时间不早于结束时间、非 IANA 时区、未知粒度、超出允许组合或缺少任一必填值 MUST 作为稳定参数错误拒绝，且不得擅自补默认范围或更换粒度。

#### Scenario: 合法显式时间范围被规范化
- **WHEN** 调用方提供合法的带偏移量起止时间、IANA 时区、受支持粒度和当前口径版本
- **THEN** 系统生成包含 UTC 起止 Instant、原始 IANA 时区、粒度和口径版本的不可变查询上下文，且相同语义输入产生相同规范化结果

#### Scenario: 时间参数不完整或组合不受支持
- **WHEN** 起止时间只提供一个、时间不递增、包含亚秒精度、时区或粒度未知，或跨度与粒度组合超过配置策略
- **THEN** 系统在访问 New API 前以参数错误拒绝请求，不执行无界查询、不替换时间范围也不自动降低粒度

#### Scenario: 相邻范围不重复边界记录
- **WHEN** 两个查询范围分别为 `[A,B)` 与 `[B,C)`
- **THEN** 时间为 `B` 的记录只属于第二个范围，上游包含式秒级结束参数由基础设施统一转换且不会造成重复

### Requirement: 分桶遵循用户时区并显式补齐空桶
系统 SHALL 根据查询上下文中的粒度和 IANA 时区生成有序桶边界，再以记录的 UTC 时间归桶。返回的桶序列 MUST 覆盖整个查询范围；没有记录的桶 MUST 以明确零计数的空桶表示，而字段不可用不得用空桶零值代替。自然日和自然小时边界 MUST 遵循该时区的规则，夏令时切换不得按固定 24 小时日长推算。

#### Scenario: 空范围仍返回完整桶序列
- **WHEN** 合法查询范围内没有任何可聚合记录
- **THEN** 系统按请求粒度返回覆盖该范围的有序空桶，且每个桶使用 `[bucketStart,bucketEnd)` 边界

#### Scenario: 夏令时开始日按 23 小时处理
- **WHEN** 查询覆盖存在春季夏令时跳变的 IANA 时区自然日
- **THEN** 日桶仍对应该时区的一个自然日，其 UTC 跨度为实际的 23 小时，记录不会落入不存在的本地小时

#### Scenario: 夏令时结束日重复小时不混淆
- **WHEN** 查询覆盖存在秋季夏令时回退的 IANA 时区自然日
- **THEN** 两个本地显示相同但偏移量不同的小时具有不同 UTC 边界，记录只进入各自对应的桶

### Requirement: 上游分页读取具有共享查询预算
系统 SHALL 通过受控读取器访问需要分页的 New API 数据源。一次聚合的全部来源读取 MUST 共享最大页数、最大记录数、单次调用超时和总耗时预算；读取器 MUST 只在确认范围内全部记录已读取后返回完整结果。达到任一保护上限、页总数前后矛盾、预期仍有数据却提前空页或总预算耗尽时 MUST 明确失败，不得返回部分数据冒充完整聚合。

#### Scenario: 多页结果完整读取
- **WHEN** 上游在预算内返回总数一致、页序连续且最终完整的多页数据
- **THEN** 读取器只返回属于 `[startTime,endTime)` 的完整规范化记录集，并报告实际调用数、页数和记录数

#### Scenario: 首页总数已经超过记录上限
- **WHEN** 上游第一页声明的总记录数超过本次查询最大记录数
- **THEN** 读取器立即以保护性拒绝结束，不继续拉取后续页，也不把第一页作为完整结果返回

#### Scenario: 多来源共同耗尽预算
- **WHEN** 同一聚合先后读取成功日志、错误日志或其他分页来源，累计页数或记录数达到共享上限
- **THEN** 后续读取被拒绝，整个聚合失败且不会只返回已完成来源的结果

#### Scenario: 上游分页在读取期间不一致
- **WHEN** 后续页的总数与首页不一致、返回重复页、或在总数未满足前出现空页或异常短页
- **THEN** 系统将结果视为不完整并明确失败，不根据现有数据估算缺失部分

### Requirement: 聚合只使用冻结基线允许的字段语义
系统 SHALL 将 New API 原始 DTO 转换为 Portal 自有的不可变聚合记录，并依据 `p2-2026-09-22-a` 或后续显式发布的基线版本决定字段可用性。只有标记为 `已验证` 的字段可以作为确定值参与正式计算；`存在差异`、`条件可用` 或 `不可用` 的字段 MUST 保持明确缺失或不可用状态，除非新证据发布了新的口径版本。Token 和时长累计 MUST 检测溢出，quota/金额累计 MUST 使用十进制语义且不得在累计阶段提前舍入。

#### Scenario: 已验证字段进入规范化记录
- **WHEN** 上游日志包含基线已验证的时间、Token、耗时、token ID、模型、request ID 和原始 quota 字段
- **THEN** 这些字段按冻结单位进入 Portal 自有记录，业务聚合无需依赖 New API DTO 或字段名

#### Scenario: 条件可用金额换算不伪装为确定金额
- **WHEN** 原始 quota 可读取但 `quotaPerUsd` 仍未取得独立证据
- **THEN** 系统可保留原始 quota 供受控计算，但正式货币金额及币种保持不可用，不使用配置默认值生成确定消费金额

#### Scenario: 未验证错误类型不生成确定成功率
- **WHEN** 失败日志类型或状态映射在当前基线中仍为条件可用
- **THEN** 正式成功率相关输出保持不可用，系统不得把未知日志排除后显示为 100% 成功

#### Scenario: 累计发生数值溢出
- **WHEN** Token、耗时或其他整数累计超出可表示范围
- **THEN** 聚合明确失败并记录安全诊断原因，不环绕为负数或截断为错误结果

### Requirement: 聚合缓存与并发合并严格隔离查询身份
系统 SHALL 只缓存 Portal 自有的只读聚合结果，并对相同键的并发计算执行单次加载合并。缓存键 MUST 包含操作命名空间、用户 ID、规范化起止时间、粒度、IANA 时区、口径版本以及所有影响结果的筛选条件；键和值 MUST NOT 包含认证 Cookie、Access Token、完整 API Key、供应商密钥或 New API 原始响应。缓存 MUST 具有短期 TTL 和最大条目数，失败、超时、取消或保护性拒绝不得作为成功结果缓存。

#### Scenario: 同用户同查询安全复用缓存
- **WHEN** 同一用户在 TTL 内以相同规范化查询和筛选条件重复请求同一聚合操作
- **THEN** 系统返回相同只读结果且不重复访问上游，并记录缓存命中

#### Scenario: 不同用户不能共享结果
- **WHEN** 两个用户提交除用户身份外完全相同的查询
- **THEN** 两次查询使用不同缓存键，各自执行或读取本用户结果，不发生跨用户复用

#### Scenario: 同键并发请求只加载一次
- **WHEN** 多个并发请求在缓存未命中时使用同一完整缓存键
- **THEN** 只有一个加载过程访问上游，其余请求等待并复用该成功结果

#### Scenario: 失败加载可重新尝试
- **WHEN** 同键加载因上游异常、超时、取消或保护上限失败
- **THEN** 失败不进入结果缓存且并发占位被清理，后续请求能够重新执行加载

### Requirement: 聚合保护参数由环境隔离配置约束
系统 SHALL 通过 `.properties` 配置聚合范围策略、分页与记录上限、超时、缓存 TTL 和容量，并在共享默认配置及 dev、test、prod 环境中显式给出或继承可追溯值。配置 MUST 在启动时校验为自洽的正值组合；当前缺少典型数据量证据时，默认最大 10 页、200 条记录、单次上游调用不超过 5 秒、聚合总预算不超过 30 秒，30 天实时日志扫描 MUST 默认禁用。

#### Scenario: 启动时发现矛盾配置
- **WHEN** 最大记录数小于单页大小、总超时短于单次调用超时、TTL 非正数或口径版本不受当前实现支持
- **THEN** 应用启动失败并指出公开配置项，不带不安全的隐式回退值运行

#### Scenario: 30 天实时扫描没有性能证据
- **WHEN** 调用方请求需要扫描 30 天日志且没有显式发布的新性能基线允许该数据源
- **THEN** 系统在上游分页前拒绝实时扫描，并提示使用较小范围或等待独立预聚合方案，不尝试全量分页

### Requirement: 聚合过程可观测且不泄露高敏或高基数信息
系统 SHALL 记录聚合总耗时、上游调用数、读取页数与记录数、缓存命中/未命中/并发合并、超时及保护性拒绝原因。指标和结构化日志标签 MUST 使用操作类型、结果类型和有限原因枚举等低基数值，MUST NOT 使用用户 ID、时间范围、模型 ID、API Key、request ID、会话或原始异常消息作为指标标签，也不得记录原始日志正文或认证信息。

#### Scenario: 成功聚合产生有限观测数据
- **WHEN** 聚合在预算内成功完成
- **THEN** 系统记录耗时、调用/分页/记录计数及缓存结果，且所有标签来自固定低基数集合

#### Scenario: 保护性拒绝可诊断但不泄密
- **WHEN** 查询因范围、页数、记录数或总超时保护而失败
- **THEN** 系统记录对应有限原因和当前 requestId 以便追踪，但不记录用户身份、凭证、完整筛选值或上游原始响应
