## Context

用户于 2026-10-03 明确取消协议和首 Token 延迟内容，见 proposal.md。此前页面已实现两项展示，但真实 other.frt 计量首个流式事件而不保证首输出 Token，协议转换链也未冻结全面映射。本地补验已取得 type=5 错误日志和 500000 quota/USD 的实际消费交叉证据。

## Goals / Non-Goals

**Goals:** 收缩已有页面为基础日志、流式状态和费用说明，保留 API 和查询行为兼容，并准确记录需求取消。

**Non-Goals:** 不实现协议/TTFT 映射或采集，不改变金额换算、分页、筛选、数据写入与其他第二阶段任务，不删除历史实测证据。

## Decisions

### 1. 删除两个展示项，保留兼容字段

桌面表格和移动卡片删除 protocol 与 TTFT，移除 TTFT 说明按钮、状态、函数、专属样式和中英文文案；即使响应包含非空增强值也不展示。保留 API 字段及前端已有独立归一校验，旧响应省略或可选值异常仍不影响合法基础页。后端继续显式返回两个 null，不解析 other 或建立新映射。

直接删除 DTO 会改变既有 API；因此取消用户展示和数据实现范围，但不做接口破坏性删除。将两个指标隐藏于详情仍保留需求负担，因此不采用。

### 2. 保留基础信息与精确费用

列顺序为时间、Key、模型、流式状态、输入/输出 Token、总耗时、结果、费用、请求 ID。移动卡片字段一致。费用保留服务端 amount/currency/quota 字符串，复用 QuotaMoneyConverter 与现有舍入，不浮点重算。费用说明按钮仍可键盘操作，说明列表不等于额外收费项目或正式账单及逐条/合计舍入差异。

### 3. 查询、安全与证据不变

沿用现有提交式筛选、服务端分页、URL 恢复、Dashboard 下钻、迟到响应隔离和会话失效缓存清理。协议/TTFT 与任意用户查询参数仍拒绝；不透传上游正文、渠道、供应商错误或其他敏感字段。

真实时间字段 created_at 与空白邮箱 null 兼容修复保留。本地错误/扣费证据只声明本地实例已验证，不外推供应商账单、其他实例或 stat 时间过滤能力。

### 4. 任务和验收状态

原 6.1 从活动任务移出并明确标注取消，不勾选为验证通过。此前已完成的工作记录保留为历史事实，新增取消落实任务；完成当前范围的代码、测试和文档后可标记 P2-09 当前范围完成，后续是否归档由用户决定。

## Risks / Trade-offs

- [兼容字段仍存在，可能被误解为指标仍在开发] → spec 与文档明确只有兼容用途，非空映射无当前交付承诺。
- [删除测试误伤费用或基础信息回归] → 保留相关测试，替换取消项展示断言为不展示断言，验证桌面/375px/中英文与费用说明。
- [旧文档保留原验收状态] → 文档顶部标注现行取消决定，历史记录保持时间和语义，不把取消伪装为验证成功。

## Migration Plan

无需数据迁移。先同步规划，再修改页面与测试，运行前端 test/lint/build、请求日志 Playwright、OpenSpec strict 与 diff 检查。保留未提交改动；在用户既有本地 Docker 测试授权下，将最新前端打入 JAR 并更新现有本地测试镜像，核对产物与页面。后端未改，沿用上轮完整 765 项验证。不得自动归档或发布。
